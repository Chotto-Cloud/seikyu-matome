# 頼み方 7: 自分の請求書ソフトに合わせる(おまけ)

## この段で作る物
このアプリが書き出す明細 CSV を、**お使いの請求書ソフトの CSV 取りこみの形**に変えます。うまく合えば、月末に CSV を取りこむだけで、請求書の「下書き」まで自動で作れます。

このアプリの CSV は、どのソフトにも合わせていません。ソフトごとに、列の名前も並びも違います。だから、合わせるときは、**そのソフトの見本ファイル**が要ります。見本なしで作ると、ほぼ確実に取りこみで断られます。

第6段まで終わってから、必要な人だけ進めてください。

## 先に確かめること
- お使いの請求書ソフトに、CSV の取りこみ(一括登録、インポートなど)があるか。無い場合は、この段は進められません。第6段までの CSV を、表計算ソフトで見て使ってください。
- ソフトの**利用規約**を読み、CSV の取りこみを使ってよいか、自動で作った CSV を取りこんでよいかを確かめます。
- できれば、練習用のアカウントや、無料のプランで試します。仕事で使っている、本物の取引先が入ったアカウントでは試さないでください。

## 準備: 見本ファイルを手に入れる
1. お使いの請求書ソフトの**公式ヘルプ**で、「CSV 取りこみ」「CSV アップロード」などの説明を探します。
2. 説明の中にある**見本ファイル(テンプレート)**をダウンロードします。ふつう、1行目に列の名前が並んだ CSV です。
3. 見本ファイルを、**開かずに**(Excel などで開いて保存し直さずに)、作業フォルダーの `sample/` に入れます。
   - 開いて保存し直すと、文字コードや列の名前が変わることがあります。
   - 見本の中身が、本物の取引先の名前だったら、使わないでください。見本は、1行目の列名だけがあれば足ります。
4. 見本ファイルの**文字コード**(UTF-8 か Shift-JIS か)と、**改行**を、ヘルプで確かめます。分からなければ、AI に聞くか、ソフトに問い合わせます。
5. 取引先を先に登録する決まりがあるか、同じ請求書番号を二重に取りこむとどうなるか、も、ヘルプで確かめます。

## 貼る物
下の「AI に貼る文」、`仕様書.md` の第4章、**第6段まで終わった `index.html` の全文**、見本ファイルの**1行目(列名)だけ**を、この順に貼ります。

- 見本ファイルの2行目以降に、本物の名前や金額があれば、貼らないでください。1行目だけで足ります。
- 本物の取引先名・金額・振込先は、AI に貼りません。

## AI に貼る文

```
あなたは、Webアプリを作る手伝い役です。私は初心者です。分かりやすい日本語で答えてください。

「請求まとめ」の明細CSV(いまはふつうのCSV。列の並びは仕様書4.2のとおり)を、私が使っている請求書ソフトの「CSV取りこみ」の形に変えたいです。
このあとに、「仕様書の第4章」「いまの index.html」「請求書ソフトの見本ファイルの1行目(列名)」を貼ります。

【先にしてほしいこと】コードを変える前に、次の対応表を作って、私に見せてください。
- 見本ファイルの列(1列目から順に)ごとに、「このアプリのどの値を入れるか」。例: 「3列目 = 発行日」。
- 対応するものが無い列は、「空にする」か「固定の値を入れる」か、私に聞いてください。決めつけないでください。
- このアプリに無い値が必須の列があれば、教えてください(作り話で埋めないでください)。
- 1つの請求書を1行にして、明細を横に並べる形のソフトもあります。見本がそういう形かどうかも、判断して教えてください。
私が「その表でよい」と言ってから、コードを変えてください。

【変える所】
1. 見出しの定数 HDR_LINES を、見本ファイルの1行目と、**1文字も変えずに**同じにする(括弧の中の説明文、全角と半角、空白、順番もそのまま)。
2. 明細CSVを作る関数 invoiceCsv() を、対応表のとおりに作り直す。
3. 文字コードと改行は、ソフトの決まりに合わせる(例: Shift-JIS が必要なら、そのとおりに。ブラウザだけで作れない場合は、そう言ってください)。
4. ファイル名は、分かりやすい名前にしてよい。
5. ソフトに取引先CSVや品目CSVの取りこみもあれば、同じように HDR_CUS と customerCsv()、HDR_ITEM と itemCsv() も、見本があれば合わせる。見本が無いものは、変えない。

【変えない所】
- <meta http-equiv="Content-Security-Policy" …>(外への通信を止める設定)
- 入力した文字を画面に出すときは textContent か value を使う(innerHTML に入れない)
- 外へ送る通信(fetch など)を足さない
- 金額・税の計算はしない(単価と数量を渡すだけ)
- const DEMO=false; の行
- CSV以外の機能(入力、設定、控え、元に戻す、カレンダーなど)

【自分で確かめてください】
- 見本ファイルの1行目と、HDR_LINES が、1文字も違わないことを確かめるテストを書いてください(tests/csv-check.test.js を直す)。
- ダミーのデータ(ダミーA社、ダミー作業、架空銀行 サンプル支店 普通 0000000)で作った CSV の、全部の行で列の数がそろうことを確かめてください。
- 取りこみで断られそうな点(必須の列が空、日付の形が違う、数字にカンマが入る、など)を、見本の説明から拾って、一覧にしてください。

【出力のしかた】
- 最初に対応表だけを出す。私が「よい」と言ったら、index.html の変えた関数と定数を、置き換え先の名前つきで出す(全文でなくてよい)。
- 最後に、変えた所と理由を、短い一覧で書く。
```

## 確かめ方(ダミーで取りこむ → 下書きで中身を見る → 下書きは消す)
1. アプリで「ダミーを入れて試す」を押し、合わせた形の CSV を保存します(月は、ダミーを入れた月)。
2. 保存した CSV を、**開かずに**、ソフトの CSV 取りこみから、そのまま取りこみます。
3. エラーが出たら、出た文をそのまま AI に貼って、直してもらいます(貼るのは、ダミーのデータの CSV だけです)。
4. 取りこめたら、ソフトの画面で**下書き**の中身を見ます。**発行はしません。**
   - 取引先、日付、品目、数量、単位、単価、合計が、ダミーのとおりか。
   - 振込先や、件名が入っているか。
   - 税の計算結果が、ソフトの設定どおりか(このアプリは、税の計算をしません。ソフトの設定が使われます)。
5. 確かめ終わったら、**下書きと、ダミーの取引先を、ソフトの画面で消します。** アプリでも「ダミーを消す」を押します。

## よくある失敗
- **1行目を1文字でも変えると、断られる**: 見本の列名は、括弧の中の説明文も含めて、そのまま使います。AI が「読みやすく直しました」と言いかえていないか、見出しの比べ(`確かめ方.md` の3)と同じやり方で確かめます。
- **文字コード**: UTF-8 のつもりが、ソフトは Shift-JIS だった(または逆)。文字化けしたり、「文字コードが正しくありません」と断られたりします。見本ファイルの文字コードに合わせます。
- **登録済みの取引先を二重に送る**: ソフトに取引先がもう登録されているのに、取引先 CSV も取りこむと、重複で断られることがあります。アプリでは、取引先に「請求書ソフトに登録済み」のチェックを付けると、取引先CSVに入らなくなります。
- **同じ請求書番号を二重に送る**: 同じ月の CSV をもう一度取りこむと、請求書番号の重複で断られる(または、二重にできてしまう)ことがあります。作り直すときは、ソフトの下書きを先に消します。
- **Excel で開いて保存し直す**: 文字コードや列の形が変わって、断られます。取りこむ CSV は、開かずに使います。

## 注意
- ソフトの**利用規約**を、必ず読んでください。自動で作った CSV の取りこみが、禁止されているソフトもあるかもしれません。
- **本物のデータを AI に貼らない**: 取引先名、金額、振込先、住所、電話、メール、控えのファイル、ソフトの画面のスクリーンショットは、貼りません。ダミーだけを使います。
- 取りこみで「下書き」ができても、請求書は、**発行する前に、必ず自分で中身を確かめてください。**
- ソフトの CSV の形は、変わることがあります。取りこみで急に断られたら、公式ヘルプで新しい見本を探し、この段をやり直します。
- 練習として作った、非公式の、無保証の資料です。うまく動くことは、お約束できません。
