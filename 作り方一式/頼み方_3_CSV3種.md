# 頼み方 3: ふつうの CSV 3種

## この段で作る物
明細 CSV・取引先 CSV・品目 CSV、警告(止める物と、※で通す物)、「CSVに書き出す(くわしく)」の枠、「3 書き出す」の列のボタンを足します。**この段が、いちばん大事です。** 見出しの行が1文字違うだけで、見本とずれて、あとで自分の請求書ソフトに合わせるときに困ります。

仕様書で従う所: 第4章(全部)、第5章(全部)、第7章、第6章の6.9〜6.12、第8章の8.5の「3 書き出す」の列と8.6。

## 貼る物
下の「AI に貼る文」、`仕様書.md` の全文、**第2段で出来た `index.html` の全文**を、この順に貼ります。そのあとに、見本の CSV(`../sample/明細_見本_A社.csv` の中身。4行だけの、架空のデータです)も貼ります。あわせて、そのファイルを、自分の作業フォルダーの `sample/` に同じ名前でコピーしておきます(テストが読みます)。

## AI に貼る文

```
あなたは、Webアプリを作る手伝い役です。私は初心者です。分かりやすい日本語で答えてください。

「請求まとめ」を6段に分けて作っています。今は第3段(ふつうの CSV 3種)です。
このあとに「仕様書」と「第2段で出来た index.html」を貼ります。仕様書に従って、index.html を拡張してください。今ある部品のIDと関数の名前は、変えないでください。

【従う所】第4章(全部)、第5章(全部)、第7章、第6章の6.9〜6.12、第8章の8.5の「3 書き出す」の列と8.6。

【いちばん大事な決まり】
- CSV の1行目(見出し)は、仕様書4.2・4.3・4.4に書いてある行を、1文字も変えずに、そのまま定数 HDR_LINES・HDR_CUS・HDR_ITEM に入れてください。3つとも文字列の配列です。言いかえ、並べ替え、空白の追加、全角と半角の入れかえは、すべて禁止です。
- 明細 CSV の列の並びは、仕様書4.2の表のとおりです。1つの記録が1行で、請求書(取引先)ごとにまとめ、その中は日付の順に並べます。
- 3つの CSV は、どれも UTF-8 で、先頭に BOM(﻿)を付け、改行は CRLF にします。最後の行のあとにも改行を付けます。引用符の決まりは仕様書4.1。
- ファイル名は、明細_YYYY-MM.csv・取引先_YYYY-MM.csv・品目_YYYY-MM.csv です。
- 税と源泉の計算はしない。単価と数量と、行ごとの「金額(単価×数量・目安)」、税区分・源泉の「指定」を書くだけ。
- 画面に出す文字は、textContent で入れる。innerHTML は使わない。

【足す物】
1. HDR_LINES・HDR_CUS・HDR_ITEM。invoiceCsv() / customerCsv() / itemCsv() と、引用符の関数 q()。ダウンロードは Blob と <a download>(type は text/csv;charset=utf-8)。ファイル名は仕様書第4章。
2. 請求書番号・コード・発行日と期限・件名の置き換え({y} {m})。
3. 税の扱い(5.3・5.4): 税区分と源泉徴収は、品目の設定をそのまま各行に書く。
4. 警告 problems() と、止めるかどうかの blocking()。文言は仕様書第7章のとおり。「※」で始まる文は通す、始まらない文は止める。
5. 「CSVに書き出す(くわしく)」の枠(8.6): 発行日 #issue、期限 #due、「予定も含める」#withPlan、プレビュー #out、警告 #warn、取引先ごとの合計 #totals、取引先CSV #dlCus、品目CSV #dlItem、案内と手順の文。
6. 「3 書き出す」の列(8.5): #outSummary、#bills(金額の目安(単価×数量)、6.9)、#dlInv、#csvReason。ボタンの状態は6.11の表(csvState)。振込先が前回と違うときの確かめ(6.11)。

【作らない物】1行で入れる欄、カレンダー、削除の別窓、デモ版。

【自分で確かめてください】
- 仕様書4.2「見本どおりになる例」の条件で作った明細CSVが、このあとに貼る見本のCSV(sample/明細_見本_A社.csv)と1文字も違わなくなるよう作ってください。
- ブラウザを使わずに、Node.js で確かめるテストを tests/csv-check.test.js として書いてください。index.html の最後の <script> の中身を取り出し、node:vm で動かします。画面の部品は「見かけだけの部品」(getElementById が、プロパティを自由に持てる偽の部品を返す。value・checked・textContent・children・addEventListener・append・replaceChildren などを持つ)で代用し、localStorage・confirm・URL・Blob も偽物を渡してください。テストの内容は、(a)3つの見出しの行が、仕様書の行と同じ、(b)見本の条件で invoiceCsv() の結果が見本ファイルと同じ、(c)3つの CSV の列数(21・14・5)が、全部の行でそろう、(d)取引先CSV・品目CSVの形、(e)先頭の BOM と、改行が CRLF であること。実行は  node --test tests/csv-check.test.js 。
- 日付は日本時間に固定してください(process.env.TZ = "Asia/Tokyo" をファイルの先頭で)。

【出力のしかた】
- index.html の全文と、tests/csv-check.test.js の全文を、それぞれ1つのコードブロックで、省略せずに出してください。
- 最後に、足した所と、仕様書から外れた所があればその理由を、短い一覧で書いてください。
```

## 終わったと言える条件

- [ ] 第2段までの条件が、まだ全部通る。
- [ ] 3つの見出しの行が、仕様書4.2・4.3・4.4の行と1文字も違わない(`確かめ方.md` の「3. 見出しの行を比べる」)。
- [ ] 見本の条件(仕様書4.2)で作った明細 CSV が、`../sample/明細_見本_A社.csv` と1文字も違わない(`確かめ方.md` の「4. 見本のCSVと比べる」)。
- [ ] 3つの CSV とも、1行目の列の数(仕様書第4章)と、どの行の列の数もそろっている。
- [ ] 3つの CSV の先頭に BOM があり、改行が CRLF で、最後の行のあとにも改行がある。
- [ ] 単価が未設定・振込先が空・コードが空か重複、のとき、明細CSVのボタンが押せなくなり、理由が出る。予定が残るときは押せて、理由の文が出る。
- [ ] 画面のプレビューに、税額や合計金額が出ていない(「金額の目安(単価×数量)」だけ)。

## 人が確かめること

1. `確かめ方.md` の2〜4に従い、ダミーでCSVを作る。
2. 保存した明細 CSV を、Excel などの表計算ソフトで開き、日付・サービス・数量・単価・金額(単価×数量・目安)・振込先が合っているか見る。見たら、保存し直さずに閉じる(文字コードや列の形が変わることがあります)。

## うまくいかないとき
- 見本と1文字違う: 違う箇所を `確かめ方.md` の方法で見つけ、その箇所だけを AI に伝えます(例: 「9列目の日付が空です」)。
- 見出しの行が仕様書と違う: AI に「見出しの行を仕様書のとおりに、定数として書き直してください。言いかえはしないでください」と頼みます。
- Excel で開くと文字が化ける: 先頭の BOM が付いているか確かめます。
