# 確かめ方

作った `index.html` を、自分の目で確かめる手順です。AI が「できました」と言っても、必ずここで確かめてください。チャットの AI は、作った物を動かせないことが多く、テストの結果の見立てを間違えることもあります。結果は、自分でコマンドを流して見ます。

> 練習として作った、非公式の、無保証の資料です。

本物の取引先名・金額・振込先は使わず、ダミー(実用版は ダミーA社・ダミー作業・ダミー相談、デモ版は A社・作業サービス・相談サービス、振込先は 架空銀行 サンプル支店 普通 0000000)だけで試してください。

コマンドは、作業フォルダー(`index.html` がある所)で流します。この資料のフォルダー(`作り方一式/`)と、見本の CSV の入った `sample/` を、作業フォルダーに置いておきます。

| 番号 | 内容 |
|---|---|
| 1 | 本物のブラウザで開く |
| 2 | ダミーを入れて、CSV を作る |
| 3 | 見出しの行を比べる |
| 4 | 見本の CSV と比べる |
| 5 | デモ版を比べる |
| 6 | 画面の見た目 |
| 7 | 自分の請求書ソフトで試す(頼み方_7をやった人だけ) |
| 8 | 片付け |
| 9 | テストの流し方 |

---

## 1. 本物のブラウザで開く

- Chrome か Edge で、ファイルとして開きます(エクスプローラーでファイルをダブルクリック、または、ブラウザの画面にファイルをドラッグ)。
- **AI の「プレビュー画面」では、スクリプトが動かないことがあります。** 上に黄色い「このアプリのプログラムが、まだ動いていません」が出たままなら、プレビューではなく本物のブラウザで開き直してください。
- 画面の上に赤い枠が出たら、読み込みで問題が起きています。その文を AI に貼って、直してもらいます(個人情報は含まれません)。
- F12 キーで開発者ツールを開き、「Console」に赤いエラーが出ていないことを確かめます。
- 修正して開き直すときは、Ctrl+F5 で読み直します。
- 外へ通信しないことの確かめ: Wi-Fi を切っても、すべての機能が動くこと。

## 2. ダミーを入れて、CSV を作る

1. 画面の上の「‹ 前の月 / 次の月 ›」で、試したい月にします(例: 2026年10月)。
2. 「ダミーを入れて試す」を押します。「1 予定」「2 実績」に、ダミーA社・ダミーB社のカードが5件出ます。
3. 「3 書き出す」の列に、取引先ごとの「金額の目安(単価×数量)」が出ます。
4. 予定のカードが残っているときは、「n件とも実績にする」を押します(確かめの窓が出ます)。
5. 「3 書き出す」の「明細CSVを保存」を押します。ブラウザのダウンロードに `明細_2026-10.csv` ができます。
   - 押せないときは、列の中の赤い文(理由)を読みます。
   - 保存した CSV を、Excel などで開いて保存し直さないでください(文字コードや列の形が変わることがあります)。
6. 「CSVに書き出す(くわしく)」で、取引先 CSV・品目 CSV も保存できます(ファイル名は `取引先_2026-10.csv`・`品目_2026-10.csv`)。

## 3. 見出しの行を比べる

CSV の1行目(見出し)が1文字違うだけで、見本とずれます。あとで自分の請求書ソフトに合わせるときも、元の形が正しくないと困ります。仕様書の行と、自分のコードの行を、道具で比べます。Node.js が要ります。

道具は `作り方一式/tools/check-headers.js` です。見出しの定数(`const HDR_LINES = [` のように、空白があっても、改行で分けてあっても)を、文字で探さず、その1文だけを vm で動かして取り出します。

```
node 作り方一式/tools/check-headers.js index.html 作り方一式/仕様書.md sample/明細_見本_A社.csv
```

合格の条件は、次の3つが全部そろうことです。

- 「HDR_LINES: 仕様書の行と同じ」「HDR_CUS: 仕様書の行と同じ」「HDR_ITEM: 仕様書の行と同じ」「HDR_LINES と見本CSVの1行目: 同じ」と出て、「すべて同じです」で終わる。
- 「**飛ばし(skipped): 0件**」と出る。
- 終了のコードが 0(エラーで止まっていない)。

見本の CSV が見つからないときは、比べを飛ばさずに「失敗」になります。見本のファイルを、`sample/` に置いてください。

「固定の文字列の並びではありません」と出たときは、見出しを部品からつなげて作っています。仕様書の行を、そのまま文字列の配列として書き直してもらいます。

## 4. 見本の CSV と比べる

見本は、`sample/明細_見本_A社.csv` です(架空のデータ。デモ版のダミーで作った物です。公開の一式では、`作り方一式/` の1つ上のフォルダーにあります)。

### 方法A(おすすめ): テストで比べる
第3段で作った `tests/csv-check.test.js` が、見本の条件で作った明細 CSV と、見本のファイルそのものを比べます。

```
node --test tests/csv-check.test.js
```

終わりの集計で、`fail 0` かつ `skipped 0` なら合格です。見本のファイルが無いときは、飛ばさずに失敗になります。

### 方法B: デモ版で作った CSV を、手で比べる
1. `docs/index.html` を開き、月を「2026年10月」にして「ダミーを入れて試す」を押します。
2. 「3 書き出す」の「明細CSVを保存」を押し、できた CSV を `demo.csv` などの名前にします(デモ版のダミーでは、A社の3行[10/3 作業サービス 1.5時間、10/10 作業サービス 2時間、10/17 相談サービス 1時間]と、B社の行が入ります)。
3. 実行します。

```
node 作り方一式/tools/compare-csv.js demo.csv sample/明細_見本_A社.csv --lines=4 --allow=13,14
```

- 「違いは、許した列だけです」か「1文字も違いません」と出れば合格です。比べるのは、見出しと、A社の3行だけです。ダミーの10/3の行には開始・終了(9:00〜10:30)が入っていて、見本は空なので、13・14列目だけは違ってよいことにします。
- 違いが出たら、「何行目の何列目が違うか」が出ます。その場所を AI に伝えて、直してもらいます。

### 方法C: 実用版で、1文字だけ違う振込先にして比べる
実用版で、見本と同じ条件(仕様書4.2「見本どおりになる例」。取引先コードは `DEMO1`、件名の設定は `【デモ】{y}年{m}月分 業務委託料`、行は開始・終了なしで時間だけ入れる)を作ります。実用版は、本物の行があるのに振込先が架空のままだと保存できないので、振込先だけを「架空銀行 サンプル支店 普通 0000001」(最後が1)にします。保存した CSV を次のように比べます。

```
node 作り方一式/tools/compare-csv.js 明細_2026-10.csv sample/明細_見本_A社.csv --allow=8
```

8列目(振込先)だけが違い、ほかは同じなら合格です。

## 5. デモ版を比べる

デモ版は、実用版の `const DEMO=false;` の1行だけを替えたものです。2つのファイルの違いを調べます。

- Windows(PowerShell): `fc.exe index.html docs\index.html`
- Mac / Linux: `diff index.html docs/index.html`

違いが `const DEMO=false;` と `const DEMO=true;` の1行だけなら合格です。

## 6. 画面の見た目

画面の見た目は、各画面について、最後に1回ずつ見れば十分です。ダミーを入れた状態で見ます。

- 幅: パソコンの広い幅、半分ほどの幅(約600px)、スマホの幅(約375px)。ブラウザの窓の幅を変えるか、F12 の開発者ツールの端末表示(Ctrl+Shift+M)を使います。
- 色: ライト、ダーク(ページ下の「表示の色」)。
- 別窓: 削除の確かめ、カレンダー、取引先の登録、品目の登録。
- 見るのは4つです。(1)文字が読める。(2)ボタンが押せる大きさ(指で押せる)。(3)横にはみ出さない。(4)別窓が開いて、Esc で閉じる。

## 7. 自分の請求書ソフトで試す(頼み方_7をやった人だけ)

> お使いの請求書ソフトは、この資料とは無関係の、別のサービスです。画面や形式は変わることがあります。うまくいかなくても、この資料の作者は対応できません。

`頼み方_7_自分のソフトに合わせる.md`(チャット用か Code用)で、明細 CSV の形をお使いのソフトに合わせたときの手順です。合わせた版は `index-mysoft.html` で、元の `index.html` は残してあります。

### 7-1. 取りこむ前に、道具で確かめる
1. 見出し: 見本の1行目と、合わせた版の `HDR_LINES` が、1文字も違わないこと。

   ```
   node 作り方一式/tools/check-headers.js index-mysoft.html - sample/mysoft見本.csv
   ```

   「同じです」と「飛ばし(skipped): 0件」が出れば合格です。見本のファイル名は、自分の物に替えます。
2. **BOM(先頭の目印)は、見本のファイルに合わせます。** 見本に BOM が無いのに、CSV に付けると、断られることがあります。逆も同じです。ソフトによって違います(試した時は、明細・取引先・品目の3種とも、BOM を外す必要がありました)。見本の BOM は、`node 作り方一式/tools/read-sample-header.js sample/mysoft見本.csv` で分かります(文字コードと改行も出ます)。
3. 合わせた版のテスト(`tests/mysoft-check.test.js`)が、`fail 0` かつ `skipped 0` で通ること。
4. 元の版のテスト(`tests/csv-check.test.js` など)も、まだ通ること(`index.html` は変えていないはずです)。

### 7-2. 試しに入れる値
- 空でよい欄は、**空**にします。
- 入れるなら、ソフトのヘルプの例と同じ形の、架空の値にします。登録番号は T+13桁の数字、メールは @ の入った形、郵便番号は 123-4567、電話は数字とハイフン、のような形です。
- 「a」のような1文字は入れません(形のチェックで断られます。試した時は、登録番号・メール・郵便番号・電話が断られました)。

### 7-3. 消える列を確かめる
合わせた形に入らない列(例: 種類(予定/実績)、日付、開始、終了)があるかを、AI に作らせた一覧で見ます。それで困らないか、自分で決めます。予定を含めたまま書き出す設定にしたとき、予定と実績の区別が CSV から消えます。合わせた版には、そのときに止める警告があります。ダミーで、予定を含めて保存しようとして、止まることを見ます。

### 7-4. 取りこむ
1. ソフトの利用規約を読み、CSV の取りこみを使ってよいことを確かめます。できれば、練習用のアカウントや、無料のプランで試します。仕事で使っている、本物の取引先が入ったアカウントでは試さないでください。
2. 第2項と同じ手順で、ダミーのデータから、合わせた形の CSV を保存します。
3. **取りこむ順番は、取引先 → 品目 → 明細です。** 取引先と品目が先にソフトに入っていないと、明細が断られることがあります。取引先に「請求書ソフトに登録済み」のチェックを付けていると、取引先 CSV には入りません。
4. **取引先コードは、ソフトの一覧とそろえます。** ソフトにすでにある取引先なら、アプリの取引先コードを、ソフトのコードに合わせます。そろっていないと、別の取引先として扱われたり、断られたりします。
5. 保存した CSV を、開かずに、ソフトの CSV 取りこみから、ダミーのまま取りこみます。
6. 「下書き」ができたら、**発行はしません。** 下書きの画面で、次を見ます。
   - 明細: 日付と品目が出ている。
   - 数量と単位: 単位の出方はソフトによって違います。数量の数が合っているかを見ます。
   - 単価と合計: 設定した単価が出ている。数量×単価の合計が合っている(税の計算の結果は、ソフトによって違います)。
   - 振込先: ダミーの振込先が出ている。
7. 取りこみで断られたら、ソフトが出した文をそのまま AI に貼り、直してもらいます(本物のデータは貼りません)。

## 8. 片付け

試し終わったら、次を片付けます。

1. 請求書ソフトに取りこんだダミー(下書きの請求書、ダミーの取引先)は、ソフトの画面で消します。**下書きの「発行」は押さないでください。**
2. アプリ: 「ダミーを消す」を押します(ダミーの行と設定だけが消えます)。
3. 保存した CSV と、控えのファイル(`請求まとめ_控え_….json`)は、ダミーのものでも、いらなければ消します。
4. 共用のパソコンなら、ブラウザの「サイトのデータ」を消します。
5. AI との会話に、本物の取引先名・金額・振込先を貼っていないか、見直します。貼ってしまっていたら、その会話を消します。

## 9. テストの流し方

Node.js 20 以上が要ります。ターミナルで、作業フォルダーに移動して実行します。

```
node --test tests/csv-check.test.js
```

- ファイルを1つずつ渡します(フォルダー名だけでは動かない場合があります)。ファイルが複数あるときは、名前を並べます。
- 日付の確かめは、日本時間に固定します(テストの先頭に `process.env.TZ = "Asia/Tokyo"`)。
- 終わりの集計の `fail` が 0 で、`skipped` も 0 なら合格です。飛ばし(skipped)があるときは、見本のファイルが無いなど、確かめていない物があります。

### 見本のテストを、自分の `index.html` にかける(答え合わせ。CSV・CSP・innerHTML の所だけ)

完成見本の入った一式(`README.md` のあるフォルダー)で実行します。環境変数 `APP_HTML` に、自分の `index.html` を指定します。

- PowerShell: `$env:APP_HTML = (Resolve-Path ..\my-app\index.html).Path; node --test tests/app.test.js`
- Mac / Linux: `APP_HTML=../my-app/index.html node --test tests/app.test.js`

見本のテストは、見本と同じ部品のID・関数名・文言を前提にしています。自分のコードが仕様書と少し違うだけでも、落ちることがあります。**全部通ることは求めません。** 落ちたテストのうち、**名前に CSV・CSP・innerHTML が入っているものだけ**を見ます。それらが落ちたときは、必ず直します。ほかのテストが落ちても、見本と違う所を見つける手がかりにとどめ、直さなくてかまいません。
