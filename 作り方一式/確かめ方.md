# 確かめ方

作った `index.html` を、自分の目で確かめる手順です。AI が「できました」と言っても、必ずここで確かめてください。

> 練習として作った、非公式の、無保証の資料です。

本物の取引先名・金額・振込先は使わず、ダミー(実用版は ダミーA社・ダミー作業・ダミー相談、デモ版は A社・作業サービス・相談サービス、振込先は 架空銀行 サンプル支店 普通 0000000)だけで試してください。

| 2 | ダミーを入れて、CSV を作る |

## 1. 本物のブラウザで開く

- Chrome か Edge で、ファイルとして開きます(エクスプローラーでファイルをダブルクリック、または、ブラウザの画面にファイルをドラッグ)。
- **AI の「プレビュー画面」では、スクリプトが動かないことがあります。** 上に黄色い「このアプリのプログラムが、まだ動いていません」が出たままなら、プレビューではなく本物のブラウザで開き直してください。
- 画面の上に赤い枠が出たら、読み込みで問題が起きています。その文を AI に貼って、直してもらいます(個人情報は含まれません)。
- F12 キーで開発者ツールを開き、「Console」に赤いエラーが出ていないことを確かめます。
- 修正して開き直すときは、Ctrl+F5 で読み直します。
- 外へ通信しないことの確かめ: Wi-Fi を切っても、すべての機能が動くこと。

## 2. ダミーを入れて、CSV を作る

1. 画面の上の「‹ 前の月 / 次の月 ›」で、試したい月にします(例: 2026年10月)。
2. 「ダミーを入れて試す」を押します。「1 予定」「2 実績」に、ダミーA社・ダミーB社のカードが5件出ます。
3. 「3 書き出す」の列に、取引先ごとの「金額の目安(単価×数量)」が出ます。
4. 予定のカードが残っているときは、「n件とも実績にする」を押します(確かめの窓が出ます)。
5. 「3 書き出す」の「明細CSVを保存」を押します。ブラウザのダウンロードに `明細_2026-10.csv` ができます。
   - 押せないときは、列の中の赤い文(理由)を読みます。
   - 保存した CSV を、Excel などで開いて保存し直さないでください(文字コードや列の形が変わることがあります)。
6. 「CSVに書き出す(くわしく)」で、取引先 CSV・品目 CSV も保存できます(ファイル名は `取引先_2026-10.csv`・`品目_2026-10.csv`)。

## 3. 見出しの行を比べる

CSV の1行目(見出し)が1文字違うだけで、見本とずれます。あとで自分の請求書ソフトに合わせるときも、元の形が正しくないと困ります。仕様書の行と、自分のコードの行を、機械で比べます。Node.js が要ります。

下のスクリプトを `check-headers.js` として、自分の作業フォルダーに保存します。

```js
// 使い方: node check-headers.js index.html 仕様書.md [見本のCSV]
// index.html の HDR_LINES・HDR_CUS・HDR_ITEM が、仕様書の行と1文字も違わないかを確かめます
const fs = require("fs");
const [htmlPath = "index.html", specPath = "仕様書.md", samplePath] = process.argv.slice(2);
const html = fs.readFileSync(htmlPath, "utf8");
const spec = fs.readFileSync(specPath, "utf8").split(/\r?\n/);
const arrOf = name => {
  const s = html.indexOf("const " + name + "=[");
  if (s < 0) return null;
  const e = html.indexOf("];", s);
  return new Function("return " + html.slice(s + ("const " + name + "=").length, e + 1))().join(",");
};
const mine = { HDR_LINES: arrOf("HDR_LINES"), HDR_CUS: arrOf("HDR_CUS"), HDR_ITEM: arrOf("HDR_ITEM") };
let bad = 0;
for (const [k, v] of Object.entries(mine)) {
  if (v === null) { console.log(k + ": index.html に見つかりません"); bad++; continue; }
  const ok = spec.includes(v);
  console.log(k + ": " + (ok ? "仕様書の行と同じ" : "違います"));
  if (!ok) bad++;
}
if (samplePath) {
  const first = fs.readFileSync(samplePath, "utf8").split(/\r?\n/)[0].replace(/^\ufeff/, "");
  const ok = first === mine.HDR_LINES;
  console.log("HDR_LINES と見本CSVの1行目: " + (ok ? "同じ" : "違います"));
  if (!ok) bad++;
}
console.log(bad ? "違いがあります" : "すべて同じです");
process.exit(bad ? 1 : 0);
```

実行します(`仕様書.md` と見本 CSV は、自分の作業フォルダーにコピーしておきます)。

```
node check-headers.js index.html 仕様書.md sample/明細_見本_A社.csv
```

- 「HDR_LINES: 仕様書の行と同じ」「HDR_CUS: 仕様書の行と同じ」「HDR_ITEM: 仕様書の行と同じ」「すべて同じです」と出れば合格です。
- 「index.html に見つかりません」と出るときは、定数の名前(`HDR_LINES` など)と、書き方(`const HDR_LINES=[…];`)が、仕様書第4章と違います。AI に直してもらいます。

## 4. 見本の CSV と比べる

見本は、`../sample/明細_見本_A社.csv` です(架空のデータ。デモ版のダミーで作った物です)。

### 方法A(おすすめ): テストで比べる
第3段で作った `tests/csv-check.test.js` が、見本の条件で作った明細 CSV と見本を比べます。

```
node --test tests/csv-check.test.js
```

全部通れば、1文字も同じです。

### 方法B: デモ版で作った CSV を、手で比べる
1. 下のスクリプトを `compare-csv.js` として保存します。

```js
// 使い方: node compare-csv.js 自分で保存したCSV 見本のCSV [--lines=4] [--allow=13,14]
//  --lines: 先頭からこの行数だけを比べる(見出しの1行を含む)
//  --allow: 違ってよい列の番号(1から数える)
const fs = require("fs");
const args = process.argv.slice(2);
const [a, b] = args.filter(x => !x.startsWith("--"));
const linesArg = args.find(x => x.startsWith("--lines="));
const allowArg = args.find(x => x.startsWith("--allow="));
const allow = new Set(allowArg ? allowArg.slice(8).split(",").map(Number) : []);
const take = t => linesArg ? t.split("\r\n").slice(0, Number(linesArg.slice(8))).join("\r\n") + "\r\n" : t;
const mine = take(fs.readFileSync(a, "utf8")), sample = take(fs.readFileSync(b, "utf8"));
if (mine === sample) { console.log("1文字も違いません(同じです)"); process.exit(0); }
console.log("文字が違います。");
console.log("バイト数: 自分 " + Buffer.byteLength(mine) + " / 見本 " + Buffer.byteLength(sample));
console.log("BOM(先頭の目印): 自分 " + mine.startsWith("\ufeff") + " / 見本 " + sample.startsWith("\ufeff"));
console.log("改行がCRLF: 自分 " + mine.includes("\r\n") + " / 見本 " + sample.includes("\r\n"));
const rows = t => t.split(/\r?\n/).map(l => {
  const r = []; let c = "", q = false;
  for (let i = 0; i < l.length; i++) {
    const ch = l[i];
    if (q) { if (ch === '"' && l[i + 1] === '"') { c += '"'; i++; } else if (ch === '"') q = false; else c += ch; }
    else if (ch === '"') q = true; else if (ch === ",") { r.push(c); c = ""; } else c += ch;
  }
  r.push(c); return r;
});
const A = rows(mine), B = rows(sample);
let bad = 0;
for (let i = 0; i < Math.max(A.length, B.length); i++) {
  const x = A[i] || [], y = B[i] || [];
  if (x.length !== y.length) { console.log((i + 1) + "行目: 列の数が違います(自分 " + x.length + " / 見本 " + y.length + ")"); bad++; }
  for (let j = 0; j < Math.max(x.length, y.length); j++) {
    if (x[j] !== y[j]) {
      const ok = allow.has(j + 1);
      console.log((i + 1) + "行目 " + (j + 1) + "列目: 自分「" + (x[j] ?? "(なし)") + "」/ 見本「" + (y[j] ?? "(なし)") + "」" + (ok ? "(許した違い)" : ""));
      if (!ok) bad++;
    }
  }
}
console.log(bad ? "許していない違いが " + bad + " 件あります" : "違いは、許した列だけです");
process.exit(bad ? 1 : 0);
```

2. `docs/index.html` を開き、月を「2026年10月」にして「ダミーを入れて試す」を押します。
3. 「3 書き出す」の「明細CSVを保存」を押し、できた CSV を `demo.csv` などの名前にします(デモ版のダミーでは、A社の3行[10/3 作業サービス 1.5時間、10/10 作業サービス 2時間、10/17 相談サービス 1時間]と、B社の行が入ります)。
4. 実行します。

```
node compare-csv.js demo.csv sample/明細_見本_A社.csv --lines=4 --allow=13,14
```

- 「違いは、許した列だけです」か「1文字も違いません」と出れば合格です。比べるのは、見出しと、A社の3行だけです。ダミーの10/3の行には開始・終了(9:00〜10:30)が入っていて、見本は空なので、13・14列目だけは違ってよいことにします。
- 違いが出たら、「何行目の何列目が違うか」が出ます。その場所を AI に伝えて、直してもらいます。

### 方法C: 実用版で、1文字だけ違う振込先にして比べる
実用版で、見本と同じ条件(仕様書4.2「見本どおりになる例」。取引先コードは `DEMO1`、件名の設定は `【デモ】{y}年{m}月分 業務委託料`、行は開始・終了なしで時間だけ入れる)を作ります。実用版は、本物の行があるのに振込先が架空のままだと保存できないので、振込先だけを「架空銀行 サンプル支店 普通 0000001」(最後が1)にします。保存した CSV を次のように比べます。

```
node compare-csv.js 明細_2026-10.csv sample/明細_見本_A社.csv --allow=8
```

8列目(振込先)だけが違い、ほかは同じなら合格です。

## 5. デモ版を比べる

デモ版は、実用版の `const DEMO=false;` の1行だけを替えたものです。2つのファイルの違いを調べます。

- Windows(PowerShell): `fc.exe index.html docs\index.html`
- Mac / Linux: `diff index.html docs/index.html`

違いが `const DEMO=false;` と `const DEMO=true;` の1行だけなら合格です。

## 6. 画面の見た目

画面の見た目は、各画面について、最後に1回ずつ見れば十分です。ダミーを入れた状態で見ます。

- 幅: パソコンの広い幅、半分ほどの幅(約600px)、スマホの幅(約375px)。ブラウザの窓の幅を変えるか、F12 の開発者ツールの端末表示(Ctrl+Shift+M)を使います。
- 色: ライト、ダーク(ページ下の「表示の色」)。
- 別窓: 削除の確かめ、カレンダー、取引先の登録、品目の登録。
- 見るのは4つです。(1)文字が読める。(2)ボタンが押せる大きさ(指で押せる)。(3)横にはみ出さない。(4)別窓が開いて、Esc で閉じる。

## 7. 自分の請求書ソフトで試す(頼み方_7をやった人だけ)

> お使いの請求書ソフトは、この資料とは無関係の、別のサービスです。画面や形式は変わることがあります。うまくいかなくても、この資料の作者は対応できません。

`頼み方_7_自分のソフトに合わせる.md` で、明細 CSV の形をお使いのソフトに合わせたときの手順です。

1. ソフトの利用規約を読み、CSV の取りこみを使ってよいことを確かめます。できれば、練習用のアカウントや、無料のプランで試します。仕事で使っている、本物の取引先が入ったアカウントでは試さないでください。
2. 第2項と同じ手順で、ダミーのデータから、合わせた形の CSV を保存します。
3. その CSV を、ソフトの CSV 取りこみから、ダミーのまま取りこみます。
4. 「下書き」ができたら、**発行はしません。** 下書きの画面で、次を見ます。
   - 明細: 日付と品目が出ている。
   - 数量と単位: 単位の出方はソフトによって違います。数量の数が合っているかを見ます。
   - 単価と合計: 設定した単価が出ている。数量×単価の合計が合っている(税の計算の結果は、ソフトによって違います)。
   - 振込先: ダミーの振込先が出ている。
5. 取りこみで断られたら、ソフトが出した文をそのまま AI に貼り、直してもらいます(本物のデータは貼りません)。

## 8. 片付け

試し終わったら、次を片付けます。

1. 請求書ソフトに取りこんだダミー(下書きの請求書、ダミーの取引先)は、ソフトの画面で消します。**下書きの「発行」は押さないでください。**
2. アプリ: 「ダミーを消す」を押します(ダミーの行と設定だけが消えます)。
3. 保存した CSV と、控えのファイル(`請求まとめ_控え_….json`)は、ダミーのものでも、いらなければ消します。
4. 共用のパソコンなら、ブラウザの「サイトのデータ」を消します。
5. AI との会話に、本物の取引先名・金額・振込先を貼っていないか、見直します。貼ってしまっていたら、その会話を消します。

## 9. テストの流し方

Node.js 20 以上が要ります。ターミナルで、作業フォルダーに移動して実行します。

```
node --test tests/csv-check.test.js
```

- ファイルを1つずつ渡します(フォルダー名だけでは動かない場合があります)。ファイルが複数あるときは、名前を並べます。
- 日付の確かめは、日本時間に固定します(テストの先頭に `process.env.TZ = "Asia/Tokyo"`)。

### 見本のテストを、自分の `index.html` にかける(答え合わせ)

完成見本の入った一式(`README.md` のあるフォルダー)で実行します。環境変数 `APP_HTML` に、自分の `index.html` を指定します。

- PowerShell: `$env:APP_HTML = (Resolve-Path ..\my-app\index.html).Path; node --test tests/app.test.js`
- Mac / Linux: `APP_HTML=../my-app/index.html node --test tests/app.test.js`

見本のテストは、見本と同じ部品のID・関数名・文言を前提にしています。自分のコードが仕様書と少し違うだけでも、落ちることがあります。**全部通ることは求めません。** 落ちたテストの名前は、見本と違う所を見つける手がかりです。特に、CSV と CSP と innerHTML に関するテストが落ちたときは、必ず直します。
