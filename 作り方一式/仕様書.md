# 仕様書: 請求まとめ(版 3.0.0)

この仕様書だけで、AI が「請求まとめ」を一から作れるように書いてあります。コードは載せていません。決まりと数値と文言を載せています。

- あまたある請求書ソフトの中で、どんな自動化ができるかを考えて作った、練習作品です。特定の請求書ソフトとは無関係の、非公式のツールです。無保証です。
- 迷ったら、完成見本(`../index.html`)で確かめてください。この仕様書と見本が食い違うときは、見本を正とします。
- 文中の「」の中の文は、画面にそのまま出す文言です。

目次

1. 目的と範囲
2. 守る決まり
3. データの形と保存
4. ふつうの CSV 3種
5. 番号・コード・税・端数
6. 計算と動き
7. 警告(止める物と、※で通す物)
8. 画面の組み立て
9. 1行の読み取り
10. デモ版と build-demo
11. 見た目(色・文字・大きさ)
12. 完成見本で確かめてほしい所

## 第1章 目的と範囲

### 作る物
月ごとの作業の時間や回数(予定と実績)を入れると、どのソフトのものでもない、ふつうの CSV(明細・取引先・品目)に書き出す、小さな Web アプリです。HTML ファイル1つで動きます。お使いの請求書ソフトに CSV の取りこみがあれば、その見本の形に合わせて変えると、請求書の下書きまで自動で作れます(`頼み方_7_自分のソフトに合わせる.md`)。

- 作る CSV は3種類です: 明細 CSV、取引先 CSV、品目 CSV(第4章)。
- 版は 3.0.0 です。画面は第8章のとおりです。
- 版は2つあります。実用版(`index.html`)と、デモ版(`docs/index.html`)です。デモ版は、実用版の1行だけを替えて作ります(第10章)。

### 作らない物
- 税と源泉徴収の計算は、しません。時間(または回数)と単価を CSV に書くだけです。画面の「金額の目安(単価×数量)」と、明細 CSV の「金額(単価×数量・目安)」の列だけを出します。この金額は、税の表示や端数処理の設定を反映しません。税は計算しません。
- サーバーも、ログインも、外への通信も、ありません。
- 勤怠管理などの記録の取りこみは、ありません。
- 100万円を超える支払いの源泉徴収(20.42%)は、扱いません。選べる率は、なし・10%・10.21%だけです。
- 日をまたぐ時間の自動計算は、しません。時間の欄に直接入れてもらいます。
- 過去の月を出し直すと、今の税の設定で出ます。単価だけは、月ごとの履歴に従います。
- 保存した CSV を Excel などで開いて保存し直すと、文字コードや列の形が変わることがあります。アプリはこれを防げません。取りこみに使う CSV は、開かずにそのまま使うのが安全です。

## 第2章 守る決まり

### 2.1 単一の HTML
- ファイルは `index.html` の1つだけです。CSS も JavaScript も、その中に書きます。
- `<title>` は「請求まとめ(試作品)」です。`<html lang="ja">` にします。
- `<head>` の最初のほうに、`<meta charset="utf-8">` と、`<meta name="viewport" content="width=device-width, initial-scale=1">` を置きます。
- `<script>` は2つです。
  1. `<head>` の中の短い1つ: `window` の `error` 出来事を受け取り、画面の先頭に赤い枠(`id="fatal"`、`role="alert"`)を出して、「画面の読み込みで問題が起きました。この文をそのまま、作者(自分の連絡先)に伝えてください(個人情報は含まれません): 」+ エラーの文 + 「 / 行 」+ 行番号 を出します。
  2. `<body>` の最後の、主なスクリプト。テストは「最後の `<script>`」を読み取るので、主なスクリプトは必ず最後に置きます。
- 外のファイル、外の URL、`<link>`、`@import`、画像ファイル、Web フォントは、使いません。

### 2.2 外への通信なし(CSP の中身そのもの)
`<head>` に、次の meta を一字一句そのまま入れます。

```html
<meta http-equiv="Content-Security-Policy" content="default-src 'none'; script-src 'unsafe-inline'; style-src 'unsafe-inline'; img-src data:; form-action 'none'; base-uri 'none'">
```

- `connect-src` は足しません。足すなら、送信先と理由を先に人に見せます。
- `unsafe-eval`、`http:`、`https:`、`*` は入れません。
- `fetch`、`XMLHttpRequest`、`sendBeacon`、`WebSocket`、`importScripts` は、コードに書きません。
- meta では `frame-ancestors` が効きません。公開するときは、同じ内容を `_headers` にも置きます。`_headers` の中身は次のとおりです(Cloudflare Pages などで使う形)。

```
/*
  Content-Security-Policy: default-src 'none'; script-src 'unsafe-inline'; style-src 'unsafe-inline'; img-src data:; form-action 'none'; base-uri 'none'; frame-ancestors 'none'
  X-Content-Type-Options: nosniff
  Referrer-Policy: no-referrer
```

- 決まり: meta の CSP の各項目が、`_headers` の CSP にそのまま含まれていること。`_headers` には、さらに `frame-ancestors 'none'` が含まれていること。

### 2.3 innerHTML を使わない
- 入力された文字を画面に出すときは、`textContent` か `value` を使います。`innerHTML` には入れません。
- 部品は `document.createElement` で作ります(短い関数 `el(tag, class, text)` を用意すると楽です)。
- 例外は2か所だけです。設定の2つの表(取引先の表・品目の表)の見出し行(`<tr><th>…</th></tr>` の固定の文字)を `innerHTML` で入れます。ここには、入力された文字は入りません。

### 2.4 税と源泉の計算をしない
第1章のとおりです。CSV に入れるのは、単価と数量と、行ごとの「金額(単価×数量・目安)」(単価×数量を円に丸めたもの。税の表示や端数処理の設定は反映しない)と、税区分・源泉徴収の「指定」だけです。税額や、税込の合計は、CSV にも画面のプレビューにも入れません。画面の「金額の目安(単価×数量)」は、単価×数量を足して、円に丸めたものです(6.9)。

### 2.5 保存場所(localStorage)の名前
名前を変えると、前の版のデータが読めなくなります。そのまま使います。

| 用途 | 実用版のキー | デモ版のキー |
|---|---|---|
| 行(rows)の配列 | `seikyu-matome-v1` | `seikyu-matome-demo-v1` |
| 設定(cfg)のオブジェクト | `seikyu-matome-settings-v1` | `seikyu-matome-demo-settings-v1` |
| 入れ方の覚え("form" か "line") | `seikyu-matome-input-v1` | 同じ |
| 表示の色("light"・"dark"・"auto") | `seikyu-matome-theme-v1` | 同じ |

- 行と設定の保存に失敗したら、画面の上の専用の場所(`id="serr"`、`role="alert"`)に「保存できませんでした。入力した内容が、このブラウザに残らないおそれがあります。この端末のブラウザの設定を確かめ、「控え(バックアップ)」でファイルに保存してください。」と出します。成功したら、その場所を隠します。ほかの文で上書きしません。
- 入れ方と色の保存に失敗しても、何も出しません(`try/catch` で黙って進みます)。
- 保存の読み込みは、壊れた中身でも止まらないようにします(`JSON.parse` の失敗は、初めの値に戻します)。

### 2.6 デモ版の切りかえ
- 主なスクリプトの先頭の近くに、次の1行を、この形のまま、ちょうど1か所だけ書きます。

```
const DEMO=false;
```

- 空白も、セミコロンも、そのままにします。デモ版を作る道具(第10章)は、この文字を探して置き換えます。ほかの場所に、同じ文字を書かないでください。

### 2.7 そのほか
- 使う JavaScript は、ふつうのブラウザの機能だけです。ライブラリは使いません。
- 日付は、この端末の時刻(日本の午前0〜9時でも前の日にならない形)で扱います。「今日」は `iso(new Date())` の1か所で決めます(`todayIso()`)。
- 行の `id` は `Date.now()+Math.random()` で作ります。
- 画面の部品の ID は、第8章の一覧のとおりにします。テストが ID で部品を探します。

## 第3章 データの形と保存

### 3.1 行(rows)
行の配列です。1行は次の形です。

```
{ id, date, client, service, hours, kind, start?, end? }
```

| 項目 | 中身 |
|---|---|
| id | 数。重ならないもの |
| date | "YYYY-MM-DD" |
| client | 取引先の名前(正規化ずみ) |
| service | 品目(サービス)の名前(正規化ずみ) |
| hours | 数。時間の品目では時間数、回の品目では回数(1以上の整数)。項目の名前は、どちらも `hours` |
| kind | "act"(実績)か "plan"(予定) |
| start, end | "HH:MM"(2桁)。時間の品目で、両方そろって正しいときだけ付く。CSV には使わない |

- 読み込むとき、`date`・`client`・`service` が文字でない行は捨てます。
- 名前の正規化 `normName(s)`: `String(s ?? "")` → NFKC → 連続する空白を1つの半角空白に → 前後の空白を除く。
- `start`・`end` を付ける条件(`timesOf`): どちらも空なら付けない。品目が「回」なら付けない。両方あり、`calcHours` が成功し、その時間が `hours` と 0.005 以内で合うときだけ付ける。合わない・片方だけのときは、行を保存しない(追加も直しも失敗)。

### 3.2 設定(cfg)
```
cfg = {
  clients:   { 名前: 取引先の設定 },
  prices:    { 品目名: 数 か "" },        // 互換のための写し。計算には使わない
  priceHist: { 品目名: [ {from:"YYYY-MM", price: 数 か ""} ... ] },
  itemReg:   { 品目名: true/false },      // 請求書ソフトに登録ずみか
  units:     { 品目名: "時間" か "回" },
  itemTax:   { 品目名: { kubun:"" か "8%(軽減)" か "非課税", wh:"なし" か "10%" か "10.21%" } },   // kubun の "" は 10%
  bank: "", subject: "{y}年{m}月分 業務委託料",
  codeSeq: 0, lastBank: "",
  dates: { "YYYY-MM": { issue?:"YYYY-MM-DD", due?:"YYYY-MM-DD" } }
}
```

取引先の設定(`cfg.clients[名前]`):

| 項目 | 中身 |
|---|---|
| code | 取引先コード(文字) |
| hon | "御中"・"様"・"なし" |
| reg | 請求書ソフトに登録ずみか(真偽) |
| regNo, dept, person, mail, zip, addr, bldg, tel, fax | 文字。どれも空でよい。前後の空白を除いて200字まで(超えたら空にする) |
| taxMode | "外税(税別)"・"内税(税込)"・"内税(免税事業者)" |
| round | "切り捨て"・"切り上げ"・"四捨五入" |

- 名前をキーにする入れ物は、`constructor` や `__proto__` という名前でも壊れないよう、プロトタイプの無いオブジェクト(`Object.create(null)` に中身を写したもの)にします。存在の確かめは `Object.hasOwn` か `in` で行います。
- 初めの値: `bank` は ""、`subject` は "{y}年{m}月分 業務委託料"。
- 表の項目のほかに、取引先の設定に別の項目が入っていても、読み捨てます(使いません)。
- 値の言い方が違う古い保存データ・控え(`hon`・`taxMode`・`round`・税区分・源泉徴収)は、読むとき(`fixCfg`・`parseBackup`)に、今の言い方へ置き換えます。置き換えの表(`LEGACY`)の中身は、完成見本で確かめてください。

### 3.3 設定をそろえる(`fixCfg`)
読み込み・控えの復元・行の追加のあとに、いつも通します。古い保存データに無い項目も、ここで作ります。

1. 取引先の名前を `normName` でそろえる。そろえた名前が重なったら、先に出たほうを残す。
2. 取引先の連絡先の項目(上の表)を整える。`taxMode`・`round` は、選択肢にあればそのまま、なければ古い全体設定(`cfg.tax`)の値、それも無ければ先頭の選択肢(外税(税別)・切り捨て)。古い版の取引先ごとの `wh`(源泉徴収)は、品目の引っ越しに使ったあと、取引先から消す。`cfg.tax` も消す。
3. 品目まわり(`fixPrices`):
   - `priceHist` の名前をそろえ、各履歴を整える(`from` が "YYYY-MM" の形、`price` が "" か0以上の数、`from` の重なりは先の1つ、`from` の昇順)。
   - `priceHist` が無い品目は、`prices` から作る: `[{from:"0000-00", price:その値}]`("0000-00" は「最初から」の意味)。
   - `prices` に無い品目は、履歴の最後の価格(なければ "")で作る。
   - `itemReg` は、品目に存在する名前の真偽値だけ残す。
   - `units` は、"時間"か"回"だけ残し、無い品目は "時間"。
   - `itemTax` は、`kubun` が選択肢に無ければ ""(古い言い方は置き換える)。`wh` は、選択肢にあればそのまま。古い形(`itemWhMigrate`)は次のとおり: 「適用する」→ 古い取引先ごとの源泉徴収が「なし」でない最初の率(無ければ "10.21%")。空欄か項目なし → その品目を使う行のうち、古い取引先の源泉徴収が「なし」でない最初の行の、その取引先の率(無ければ "なし")。「適用しない」・そのほか → "なし"。
4. `codeSeq`(取引先コードの通し番号): 保存されている整数(0以上)と、`^A(\d+)$` に合う既存のコードの最大値の、大きいほう。
5. `lastBank` は文字でなければ ""。
6. `dates` は、キーが "YYYY-MM"、値が `issue`・`due`(どちらも "YYYY-MM-DD" の形)のものだけ残す。どちらも無いものは捨てる。

行を使っていて設定に無い取引先・品目は、`ensureClients` が、描くたびに補います。取引先: コードは新しく作る(5.2)、`hon` は "御中"、`reg` は false。品目: `prices` と `priceHist` に空の値を作る。

### 3.4 控え(バックアップ)
- 保存: JSON(字下げ1)で `{ app:"seikyu-matome", version:1, savedAt:(ISO文字), rows, cfg }`。ファイル名は「請求まとめ_控え_YYYY-MM-DD.json」。
- 復元(`parseBackup`): 次の場合は、エラーにして、今のデータを変えません。
  - JSON として読めない、`app` が違う・`version` が1でない・`rows` が配列でない・`cfg` が無い: 「このアプリの控えではありません」
  - 行の `date` が "YYYY-MM-DD" でない・`client`/`service` が空・`hours` が0以上の数でない・`kind` が "plan"/"act" でない: 「n行目の内容が正しくありません」
  - `start`/`end` が "HH:MM" でない・片方だけ・終了が開始以前: 「n行目の開始・終了が正しくありません」
  - デモ版で、決まった名前以外が入っている: 第10章
- 復元した行は、新しい `id` を付けて、名前を正規化します。設定は `fixCfg` を通します(古い形も読めるように、`tax`・`wh` なども受け取ります)。
- 復元の確かめ: `confirm` に「今の入力(n行)を、控えの内容(n行、YYYY-MM〜YYYY-MMの分、保存した日時 …)で置き換えます。置き換えた直後なら「元に戻す」で戻せます(設定を変えたり、開き直したりすると戻せません)。念のため、先に今の内容を「控えを保存」で残してください。よろしいですか?」の形で出す。承知されたら置き換え、`codeSeq` は今の値と控えの値の大きいほうにして、戻せるようにする(3.5)。失敗の表示: 「戻せませんでした: …。今の入力は変わっていません。」

### 3.5 「元に戻す」の仕組み
- 戻せる操作は、直前の1つだけです。`undo = { label, rows:(操作前の行の写し), cfg:(操作前の設定の写し か null) }`。
- 戻せる操作: 行の追加・直す・実績にする・予定に戻す・削除・一括で実績にする・前の月を写す・ダミーを入れる・控えから戻す。
- `saveRows()`(行を保存するたび)は `undo` を消す。`saveCfg()` は、`undo.cfg` があるときだけ `undo` を消す。だから、1行ずつの操作は、行の保存のあとで `undo` を入れ直す(`undoable(label, msg, fn)`: 操作前の行と設定を写す → `fn()` を実行 → `fn` が null/false/undefined を返したら何もしない → `undo` を入れる → お知らせを出す)。
- 戻す(`undoLast`): 行を操作前に戻して保存。`undo.cfg` があれば設定も戻して保存し、設定の入力欄に反映。戻したら「元に戻しました。」と出す。
- 別のタブで保存が起きたとき(`storage` 出来事で、キーが行か設定のもの、または null)は、読み直して `undo` を消す。

## 第4章 ふつうの CSV 3種

3種とも、どの請求書ソフトのものでもない、ふつうの CSV です。ブラウザで文字列を作り、Blob(`text/csv;charset=utf-8`)にして、`<a download>` で保存します。

- 文字コードは UTF-8 で、先頭に BOM(`﻿`。先頭の目印)を付けます。Excel で開いても、文字が化けにくくなります。
- 改行は CRLF(`\r\n`)です。最後の行のあとにも CRLF を付けます。
- 見出しの行は、3種とも、コードの定数に持ちます(名前は下のとおり)。画面の文言や列の名前を変えるときは、定数だけを直します。

| CSV | ファイル名 | 定数 | 列の数 |
|---|---|---|---|
| 明細 CSV | `明細_YYYY-MM.csv` | `HDR_LINES` | 21 |
| 取引先 CSV | `取引先_YYYY-MM.csv` | `HDR_CUS` | 14 |
| 品目 CSV | `品目_YYYY-MM.csv` | `HDR_ITEM` | 5 |

(YYYY-MM は表示中の月です。)3つの定数は、どれも文字列の配列です。

### 4.1 引用符の決まり(3種とも同じ)
1つの値 `v` は、`String(v ?? "")` にして、`"`・`,`・`\r`・`\n` のどれかを含むときだけ、全体を `"` で囲み、中の `"` を `""` にします。含まないときは、そのままです。空の値は空(何も書かない)です。1行は、値を `,` でつないで作ります。

### 4.2 明細 CSV

- 1つの記録が1行です。請求書(取引先)ごとにまとめ、その中は日付の順に並べます。
- 1行目(見出し)は、次の1行です。**1文字も変えずに**写します。21列です。

```
請求書番号,発行日,支払期限,取引先コード,取引先,敬称,件名,振込先,日付,サービス,数量,単位,開始,終了,単価,金額(単価×数量・目安),税区分,源泉徴収,消費税の表示,端数処理,種類(予定/実績)
```

#### 列の意味(1から数えた番号)

| 列 | 見出し | 入れる物 |
|---|---|---|
| 1 | 請求書番号 | 年4桁+月2桁+「-」+取引先コード(例 `202610-DEMO1`。5.1) |
| 2 | 発行日 | 画面の「発行日」(YYYY-MM-DD)。初めは月末 |
| 3 | 支払期限 | 画面の「支払期限」(YYYY-MM-DD)。初めは翌月末 |
| 4 | 取引先コード | その取引先のコード |
| 5 | 取引先 | 取引先の名前 |
| 6 | 敬称 | 取引先の `hon`(御中・様・なし) |
| 7 | 件名 | 設定の件名の `{y}` を年(例 2026)、`{m}` を月(0を付けない。例 10)に置き換えたもの。デモ版は先頭に「【デモ】」 |
| 8 | 振込先 | 設定の振込先(デモ版は決まった架空の振込先) |
| 9 | 日付 | 記録の日付(YYYY-MM-DD) |
| 10 | サービス | 品目(サービス)の名前 |
| 11 | 数量 | 記録の `hours`(小数2桁までに丸め、末尾の0は付けない。`1.5`、`2`)。開始・終了から計算した時間も小数2桁に丸める(9:00〜9:20 なら `0.33`) |
| 12 | 単位 | その品目の単位(`時間` か `回`) |
| 13 | 開始 | 記録の `start`(`09:00` の形)。無ければ空 |
| 14 | 終了 | 記録の `end`。無ければ空 |
| 15 | 単価 | その月の単価(数。未設定は空) |
| 16 | 金額(単価×数量・目安) | 単価×数量を円に丸めた数(`Math.round`)。単価が未設定なら空。税の表示や端数処理の設定は反映しません。税は計算しません |
| 17 | 税区分 | 品目の税区分。10%→`10%`、8%(軽減)→`8%(軽減)`、非課税→`非課税` |
| 18 | 源泉徴収 | 品目の源泉徴収(`なし`・`10%`・`10.21%`) |
| 19 | 消費税の表示 | 取引先の `taxMode`(外税(税別)・内税(税込)・内税(免税事業者)) |
| 20 | 端数処理 | 取引先の `round`(切り捨て・切り上げ・四捨五入) |
| 21 | 種類(予定/実績) | 実績→`実績`、予定→`予定` |

- 列の数は、いつも21です。行が何行でも、明細を足す列はありません(1つの記録が1行だからです)。
- 税の金額や、税込の合計は、書きません(2.4)。金額は、単価×数量の「目安」です。
- 予定の行は、「予定も含める」がオンのときだけ入ります(6.10)。

### 4.3 取引先 CSV

- ファイル名: 「取引先_YYYY-MM.csv」。BOM つき・CRLF(最後の行のあとにも CRLF)。
- 1行目(見出し)。**1文字も変えずに**写します。14列です。

- 1行目(見出し)。**1文字も変えずに**写します。5列です。


- 行: 請求書ソフトに未登録の品目(`itemReg` が true でないもの)すべて。
- 5列: 品目、単価(この月。表示中の月の単価。未設定は空)、単位(時間か回)、税区分(10%→`10%`、8%(軽減)→`8%(軽減)`、非課税→`非課税`)、源泉徴収(`なし`・`10%`・`10.21%`)。

### 4.5 自分の請求書ソフトに合わせるとき
このアプリの CSV は、どのソフトにも合わせていません。お使いの請求書ソフトに CSV の取りこみがあるときは、そのソフトの見本ファイル(1行目の列名)に合わせて、明細 CSV の形を変えると、請求書の下書きまで自動で作れます。変え方は、`頼み方_7_自分のソフトに合わせる.md` にあります。合わせるときは、見出しの定数(`HDR_LINES` など)と、CSV を作る関数だけを変えます。ほかの部分は変えません。

## 第5章 番号・コード・税・端数

### 5.1 請求書番号
`年(4桁)+月(2桁)+"-"+取引先コード`。例 `202610-A001`。

### 5.2 取引先コードの作り方
- 新しい取引先には、`"A"+通し番号(3桁、0埋め)` を付けます(`A001`、`A002`…)。
- 通し番号は `cfg.codeSeq` で持ち、新しく作るたびに1つ増やします。取引先を消しても戻しません(使い回さない)。
- 「取引先を登録」の窓を開いた時の案内は `A`+(`codeSeq`+1)で、登録するまで `codeSeq` を進めません。コードは、人が書き直せます。
- 取引先コードは、設定にあるすべての取引先の中で重ならないこと。重なると保存できず、明細 CSV も止まります。
- デモ版のコードは、決まっています(10.3)。

### 5.3 税区分・消費税の表示・端数
- 品目ごとの税区分: 10%・8%(軽減)・非課税(値は、10%が空、ほかは `8%(軽減)`・`非課税`)。明細 CSV の「税区分」の列に、`10%`・`8%(軽減)`・`非課税` と書きます(4.2)。
- 10%の税区分は、いつも `10%` と書きます。8%の品目は、品目の税区分「8%(軽減)」で出します。
- 消費税の表示(外税(税別)・内税(税込)・内税(免税事業者))と端数処理(切り捨て・切り上げ・四捨五入)は、取引先ごとに選び、CSV に書くだけです。計算はしません。

### 5.4 源泉徴収
- 品目ごとに、なし・10%・10.21%から選びます。初めは「なし」です。
- 源泉徴収は、明細 CSV の1行ごとに、その品目の設定(なし・10%・10.21%)をそのまま書きます(4.2 の18列目)。請求書ごとにまとめ直しません。率の違う品目が1つの請求書に混ざっても、止めません。
- 画面の短い表示(プレビューの品目の後ろ)は、「(源泉10%)」「(源泉10.21%)」の形です。

### 5.5 発行日・期限
- 初めの値: 発行日はその月の末日。支払期限は翌月の末日。
- 人が直した値は、月ごとに `cfg.dates[YYYY-MM]` に覚える。空にすると、その分は初めの値に戻る。
- 月が変わったとき、画面の注記(`dnote`)に「この月で前に直した、発行日と支払期限を使っています。」か「月が変わったので、発行日と支払期限を、月末と翌月末にしました。」を出す。

### 5.6 単価の履歴
- `priceHist[品目] = [{from:"YYYY-MM", price}]`(`from` の昇順)。
- その月の単価(`priceFor(品目, 月)`): `from` がその月以前のもののうち、いちばん新しいものの `price`。無ければ ""(未設定)。
- 単価を変える(`setPrice(品目, 月, 値)`): その月に同じ `from` があれば消す。直前(その月より前)の単価と同じ値なら、履歴を増やさない。違えば `{from:月, price:値}` を足して並べ直す。`cfg.prices[品目]` も値にする。
- 「いま選んでいる月から先の単価になります」と画面に出す。あとの月に別の単価があれば、それは変わらないと文で知らせる。
- 数でない・マイナスは「未設定」("")として扱う(`toPrice`)。

## 第6章 計算と動き

### 6.1 時間の計算(`calcHours(開始, 終了)`)
- 両方が "HH:MM"(時 00〜23、分 00〜59)でなければ、失敗「時刻を入れてください」。
- 終了が開始以前なら、失敗「終了は開始より後の時刻にしてください(日をまたぐ時間は、時間の欄に直接入れてください)」。
- 成功: 時間 = `Math.round(分の差/60*100)/100`(小数2桁まで。0.25刻みには丸めない。例: 9:00〜9:20 は 0.33時間、9:30〜11:15 は 1.75時間)。この丸めた時間が、行の `hours` になり、明細 CSV の数量にも、そのまま書かれます。

### 6.2 数量の確かめ(`qtyError`)
- 品目が「回」: 1以上の整数。違えば「回数は、1以上の整数で入れてください。」
- 品目が「時間」: 0以上の数。違えば「時間は、0以上の数で入れてください。」

### 6.3 種類の決め方
`kindFor(date)`: `date > 今日` なら "plan"、それ以外は "act"。欄の「種類」が「日付で決める」(初めの値)のときに使う。

### 6.4 行の追加・直す・削除
- 追加(`addRow`): デモ版の名前の確かめ(第10章)、数量の確かめ、`timesOf` を通る行だけ保存。失敗は null。
- 直す(`updateRow`): 同じ。`id` は変えない。
- 削除: 別窓で確かめてから(8.9)、行を取り除き、直前の状態を `undo` に入れる。「M/D 取引先 を削除しました。」と出す。
- 実績にする / 予定に戻す: `kind` を変える。「M/D 取引先 を実績にしました。」「… を予定に戻しました。」。
- 追加したときの文: 「M/D 取引先 を実績に追加しました。」(予定なら「予定に追加」)。追加した行が表示中の月と違う月なら、「(11月に移りました)」を足し、表示の月をその行の月へ移す。直したときは「… を直しました。」。
- 表示中の年と違う年の日付には、年を付ける(例 `2027年3/5`)。ラベルは `(年)M/D 取引先`。

### 6.5 一括の操作
- **n件とも実績にする**(`actAll`): 表示中の月の予定すべて。`confirm`「n件の予定を実績にします。行っていない日が入っていないか、先に確かめてください」。承知されたら実績にし、戻せるようにして、「n件を実績にしました。」。
- **前の月の行を、予定として写す**(`copyPrev`): 前の月の行を、「第n週の同じ曜日」に、予定(`kind:"plan"`、時間帯なし)として写す。
  - 写す先の日: 現在の月の1日の曜日を `fw`、写し元の日付を `d` として `day = 1 + (d.曜日 − fw + 7) % 7 + 7 × (ceil(d.日 / 7) − 1)`。`day` がその月の日数を超える行は写さない(数える)。
  - 同じ日・取引先・サービスの行がすでにあれば写さない(数える)。
  - 写せる行が0件なら「写せる行がありません(写せない日 n件…)。」と出して終わる。
  - 写せるなら `confirm`「n件を写します(写せない日 n件…)。この月にはすでに n件あります」。承知されたら足して、戻せるようにして、「n件を予定として写しました(…)。」。
  - 前の月に行が無いとき、ボタンは押せず、理由「前の月に行がないので、写せません。」を出す。

### 6.6 ダミーを入れる / 消す(実用版)
- ダミーの名前(決まった値): 実用版は取引先 `ダミーA社`・`ダミーB社`、品目 `ダミー作業`・`ダミー相談`。デモ版は `A社`・`B社`・`作業サービス`・`相談サービス`。
- **ダミーを入れて試す**(`loadDummy`): 今のデータや設定は変えず、無いものだけ足す。すでに入力があるときは `confirm`「今の入力に、ダミーの行(C1・C2)を足します。振込先・取引先コード・単価など、今の設定は変えません。よろしいですか?」。
  - 表示中の月に、次の5行を足す(日, 取引先, 品目, 数量, 開始, 終了): (3, C1, V1, 1.5, 09:00, 10:30)、(10, C1, V1, 2)、(17, C1, V2, 1)、(5, C2, V1, 1)、(12, C2, V1, 1.5)。種類は、取引先が C1 か日が10以下なら実績、それ以外は予定。同じ日・取引先・品目・数量・種類の行があれば足さない。
  - 取引先: C1 にコード `DEMO1`、C2 にコード `DEMO2`(敬称 御中、未登録)を、無ければ足す。
  - 単価: 品目 V1 を3000、V2 を4000。履歴が空のときだけ、表示中の月から先に設定。
  - 実用版では、V2(ダミー相談)が新しい品目なら、単位を「回」にする。デモ版は、どちらも時間。
  - 振込先が空なら、架空の振込先を入れる。
  - 変わったなら、戻せるようにする(行も設定も)。文: 「ダミーの行をn件入れました。試し終わったら「ダミーを消す」を押してください。」か「ダミーはもう入っています。」
- **ダミーを消す**(`clearDummy`、実用版のみ): ダミーの取引先か品目を使っている行と、ダミーの設定だけを消す。本物は消さない。`confirm`「ダミーの名前(…)を使っている行 n件と、ダミーの設定 n件を消します。(振込先もダミーのままなので、空にします。)それ以外のデータは消しません。よろしいですか?」。消せるものが無いときはボタンを押せなくし、理由「消せるダミーがありません。」を出す。消したら「ダミーの行 n件と、ダミーの設定 n件を消しました。」。この操作は「元に戻す」の対象にはしない。

### 6.7 設定の操作
- 取引先の名前変更: 行と設定の名前をいっしょに付け替える。すでにある名前には、できない(「…はすでにあります。別の名前にしてください(1つにまとめることはできません)。」)。
- 取引先・品目の削除: 使っている行があれば削除できない(ボタンも押せなくし、「使用中(n行)のため、削除できません」)。使っていなければ `confirm`「「…」を設定から削除しますか?」。
- 品目の単位を変える: その品目を使う行があれば、`confirm`「この品目のn行の数量の意味が変わります(たとえば 1.5時間 が 1.5回 になります)。よろしいですか?」。
- 取引先の登録・編集と、品目の登録・編集は、別窓(8.8)。

### 6.8 合計
- 実績の合計・予定の合計(頭に出す、`sumText`): 時間の品目の合計と回の品目の合計を分け、「5時間 + 1回」の形。0の項目は出さない。どちらも0なら「なし」。数は小数2桁までに丸める(`fmt`: `Math.round(n*100)/100` の文字)。
- 取引先ごとの合計(「CSVに書き出す(くわしく)」の中): 「取引先名: 実績 4.5時間・3回 / 予定 1時間」。時間も回もあれば「・」でつなぐ。時間が0で回があれば回だけ。どちらも0なら「0時間」。

### 6.9 金額の目安(単価×数量)
- 取引先ごとに、(表示中の月の単価)×(数量)の合計。対象は、請求書に入る行(「予定も含める」に従う)。
- 品目の単価が1つでも未設定なら、金額は出さず「単価が未設定の品目があります」。
- 円に丸めて(`Math.round`)、`toLocaleString("ja-JP")` + 「円」。税の表示や端数処理の設定は反映しない。税と源泉は計算しない。なお、行ごとの「単価×数量」(円に丸める)は、明細 CSV の「金額(単価×数量・目安)」の列に入る(4.2)。

### 6.10 請求書に入る行(`selected`)
表示中の月の行のうち、(デモ版は決まった名前だけ)かつ(「予定も含める」がオンか、実績)のもの。取引先ごとにまとめて1枚(`groups`)。日付順。

### 6.11 明細 CSV のボタンの状態(`csvState`、上から順に決める。5通り)

| 状態 | ボタン | 理由の文(`csvReason`) |
|---|---|---|
| この月の行が1つも無い | 押せない・副 | 「記録を入れると、ここに請求書が出ます。」 |
| 止める警告が1件でもある | 押せない・副 | 赤く太字で「エラー: 」+最初の1件(末尾の「。」を除く)+(2件以上なら「(ほかn件)」)+「。下の『CSVに書き出す(くわしく)』で確かめてください」 |
| 予定が残り、「予定も含める」がオフ | 押せる・副 | 太字「まだ予定がn件あります。実績にしてから保存するのがおすすめです(予定は入りません)。」 |
| 予定が残り、「予定も含める」がオン | 押せる・副 | 太字「予定もn件、請求書に入ります。」 |
| 予定が0件(すべて実績) | 押せる・主 | 「予定がすべて実績になりました。保存できます。」 |

- 「副」はふち取りのボタン、「主」は塗りのボタンです。「3 書き出す」の列の中では、塗りのボタンになるのは、いちばん下の行(予定がすべて実績)のときの明細 CSV ボタンだけです。
- 保存の前に、振込先が前回保存した振込先(`cfg.lastBank`)と違うときは `confirm`「振込先が前回(…)から変わっています。このまま保存しますか?」。保存したら、(実用版では架空の振込先でなければ)`lastBank` を今の振込先にする。
- ファイル名は「明細_YYYY-MM.csv」。保存したら「明細CSVの保存を始めました。ブラウザのダウンロードを確かめてください。」と、帯と下の注記(`msg`)の両方に出す。

### 6.12 取引先・品目の CSV のボタン
- 取引先 CSV: 未登録の取引先が1つも無いと押せない(理由「取引先CSV: 請求書ソフトに未登録の取引先がないので、保存できません。」)。コードが空の取引先があっても押せない(「取引先CSV: 取引先コードが空の取引先があります。設定で入れてください。」)。
- 品目 CSV: 未登録の品目が無いと押せない(「品目CSV: 請求書ソフトに未登録の品目がないので、保存できません。」)。

## 第7章 警告(止める物と、※で通す物)

- 警告は文字の一覧で、下の順に作ります。**「※」で始まる文は、通す警告(保存できる)。「※」で始まらない文は、止める警告(明細 CSV の保存ボタンを押せなくする)**です。
- 画面(`warn` の一覧)では、止めるものに「エラー:」、通すものに「注意:」の文字を、先頭に付けます(色だけに頼らない)。「※ 予定の行」の警告だけは太字にします。
- 請求書に入る行(6.10)について作ります。

| 順 | 条件 | 文言 | 止める? |
|---|---|---|---|
| 1 | 請求書に入る行が1つも無い | 「この月に出せる行がありません。行った日の予定は、「1 予定」のカードの「実績にする」を押して、実績にしてください」(この1件だけを返して終わる) | 止める |
| 2 | 入る行に予定がn件 | 「※ 予定の行がn件、請求書に入ります。行っていない日も請求されます。実績に切り替えるか、「予定も含める」を外してください」 | 通す |
| 3 | 単価が未設定の品目がある | 「単価が未設定: 品目、品目」(「、」でつなぐ) | 止める |
| 4 | 振込先が空 | 「振込先が未入力です」 | 止める |
| 4' | (実用版)振込先が架空の振込先のままで、ダミーでない行が入る | 「振込先が架空(ダミー)のままです。本物の振込先に変えてください」 | 止める |
| 5 | 取引先コードが空 | 「取引先コードが空: 取引先名」 | 止める |
| 5' | 取引先コードが、設定の複数の取引先で重なる | 「取引先コードが重複: コード(名前、名前)」(同じコードは1回だけ) | 止める |
| 6 | 発行日か支払期限が空 | 「発行日と支払期限を入れてください」 | 止める |
| 8 | 時間の品目で、数量が0以下の行がn件 | 「※ 時間が0の行がn件、入っています。間違いでないか確かめてください」 | 通す |
| 8' | 回の品目で、数量が0以下の行がn件 | 「※ 回数が0の行がn件、入っています。間違いでないか確かめてください」 | 通す |
| 9 | 回の品目で、数量が0より大きく整数でない行がある | 「回数が整数でない行があります: 取引先 M/D 品目(数回)、… 。カードの「直す」で直してください」 | 止める |
| 10 | 同じ日・取引先・品目の行が重なる | 「※ 同じ日・取引先・サービスの行が重なっています: 取引先 M/D 品目、…。二重に入れていないか確かめてください」 | 通す |
| 12 | 8%(軽減)か非課税の品目が入る | 「※ 8%(軽減)・非課税の品目があります。金額の目安は単価×数量で、税の金額は計算していません。税区分の列を見て、お使いの請求書ソフトや表計算で計算してください」 | 通す |
| 12' | 入る取引先の名前・品目の名前・件名・振込先(と、未登録の取引先の連絡先)が、`=` `+` `-` `@` のどれかで始まる(全角は半角にそろえて見る) | 「※ 「名前」「名前」は、= + - @ のどれかで始まっています。表計算ソフトで数式として動くことがあります。必要なければ、頭の文字を変えてください」(件名・振込先は「件名」「振込先」、連絡先は「名前の連絡先」と書く) | 通す |
| 13 | 請求書ソフトに未登録(`reg` が false)の取引先が入る | 「※ 請求書ソフトに未登録の取引先: 名前、名前。取引先CSVで登録できたら、設定の「請求書ソフトに登録済み」にチェックを入れてください」 | 通す |

- 源泉徴収の率の違う品目が混ざっても、止めません(5.4)。税の金額は計算しないので、請求書にする前に、中身を必ず自分で確かめます。

## 第8章 画面の組み立て

画面は上から下へ、次の順に並べます。最大幅は1100px、中央ぞろえ。サイドメニューは作りません。

### 8.1 先頭の注意の枠(`div.notices`)
1. 小さな注意書き(`p.badge`): 「練習として作った、特定の請求書ソフトとは無関係の非公式な補助ツールです。無保証です。請求書の内容は、請求書にする前に、必ず自分で確認してください。」
2. 保存の失敗の場所(`#serr`、`role="alert"`、初めは隠す)
3. デモ版の帯(`#demoBanner`、初めは隠す。デモ版だけ表示): 「これはデモ版です。取引先・サービスは決まったダミーから選ぶだけです。実際に使うときは、実用版のファイルを保存して、自分のPCで開いてください」

`<body>` の先頭に `#nojs`(黄色い枠、`role="alert"`)を置きます。文: 「このアプリのプログラムが、まだ動いていません。ボタンを押しても何も起きない場合は、このファイルを Chrome か Edge で開き直してください(エクスプローラーでファイルをダブルクリック)。Claude などのアプリの中のプレビュー画面では、動かないことがあります。」主なスクリプトの最後の行で、この枠を隠します。

### 8.2 頭(`header.top`)
- 左: 小見出し「請求まとめ ・ 練習作品」。その下の `h1`: 年(`#yearLabel`、「2026年」、20px)+ 月の数字(`#monthNum`、56px、太字)+「月」(24px)+ 読み上げ用の隠し文字「の記録」。
- 月の移動: `#prevMonth`(文字は描くたびに「‹ 9月」)、`#nextMonth`(「10月 ›」)。aria-label は「前の月(9月)」「次の月(10月)」。`#thisMonthBtn`「今月に戻る」(今月を表示中は隠す)。`<input type="month" id="month">`(aria-label「月を選ぶ」、小さく)。表示中の月の状態は、この `#month` の値1つだけで持つ。
- 中: 実績の合計 `#sumAct`・予定の合計 `#sumPlan`(6.8。予定のほうは薄い色)。見出しは「実績」「予定」。
- 右のメニュー(`nav`、aria-label「メニュー」): `#openCal`「カレンダーで見る」(副ボタン、小さなカレンダーの絵つき、別窓を開く)、`<a href="#sec-settings">設定</a>`、`<a href="#sec-backup">控え(バックアップ)</a>`(副ボタンの見た目)。

### 8.3 はじめての手順(`section#guide`)

### 8.4 記録を入れる(`section#sec-enter`)
- 見出し `#addTitle`「記録を入れる」(直している間は「記録を直す」)。
- 右に切りかえ(`div.seg`、`role="group"`、aria-label「入れ方」): `#modeLine`「1行で入れる」、`#modeForm`「欄に分けて入れる」。`aria-pressed` で今の方を示す。初めは「欄」。最後に選んだ方を `seikyu-matome-input-v1` に覚える。
- `#editing`(`role="status"`、直す間だけ表示): 太字 `#editLabel`(行のラベル)+「を直しています。直したら「直した内容で保存する」を押します。」
- `form#f`(`novalidate`)。ブラウザ自身の入力チェックの吹き出しは使いません(画面や幅によって見切れるため)。同じ内容を、画面の文で出します。
  - 左(`.enter-main`): 1行の箱 `#lineBox`、欄の箱 `#formBox`、メッセージ `#fmsg`(`aria-live="polite"`、`p.note`。エラーのときは赤い太字)。
  - 右(`.enter-side`): `#submitBtn`(主、高さ52px、「追加する」/直す間は「直した内容で保存する」)、`#cancelEdit`(副、「直すのをやめる」、直す間だけ表示)。
- **1行の箱(`#lineBox`)**: 
  - `#q`(文字の入力、大きく・高さ52px・18px、ラベルは隠し文字「1行で入れる」、placeholder「例: 10/21 A 作業 9:00-11:00」、aria-describedby は `fmsg` を含む)。
  - `#qRead`(読み取りの札の場所)。
  - 「押すと欄に入ります:」+ `#pickClients`・`#pickServices`(取引先・品目の候補を、それぞれ最大8つのボタンに。押すと、名前を `key` の形で1行の末尾に差しこむ)。
  - `details.howto`「くわしい入れ方」: ①取引先とサービスは頭の文字だけで分かる(例: 「A」で「A社」や「ダミーA社」、「作業」で「作業サービス」)。②初めての名前は1行では入らない(「欄に分けて入れる」か設定で登録する)。③時間は「9:00-11:00」「9-11」「1.5h」「1.5時間」。「回」のサービスは、回数なしで1回、「2回」と書くと2回。④今日より後の日付は予定、今日までは実績。「予定」「実績」と書けば変えられる。⑤全角の数字のままでも読める。
- **欄の箱(`#formBox`)**: 次の欄が横に並びます(狭い幅では折り返す)。
  - `#date`(日付、`type=date`)
  - `#client`(取引先、文字)+ `#clientPick`(選択欄、aria-label「取引先を選ぶ」、先頭の選択肢は「▼ 選ぶ」)。placeholder「例: ダミーA社」

  - `#kind`(選択欄、ラベル「種類」): 「日付で決める」(値 auto、初めの値)・「実績」(act)・「予定」(plan)。
  - 説明 `#pickHelp`(`p.note`): 「取引先とサービスは、一度入れると、次から右の「▼ 選ぶ」に出ます(はじめは入力だけです)。「回」のサービスは、開始と終了がなくても入れられます。」
  - 選択欄は、候補が無いときは隠して無効にする。選ぶと、入力欄にその名前が入り、選択欄は先頭に戻る。
- 欄の動き:
  - 開始と終了が両方入ったら、`calcHours` で時間の欄を自動で入れる(あとで直してよい)。失敗なら文を `#fmsg` に出す。
  - 時間の欄を人が直したら、開始・終了を空にして、「時間を直接入れたので、開始・終了を消しました。」と出す。
  - 追加の前の確かめ(欄のとき)。上から順に、最初に当たったもので止め、その欄へ移る: 日付なし「日付を入れてください。」、取引先なし「取引先を入れてください(右の「▼ 選ぶ」からも選べます)。」、サービスなし「サービスを入れてください(右の「▼ 選ぶ」からも選べます)。」、数量が数でない「回数を入れてください。」か「時間を入れてください(開始と終了を入れると、自動で入ります)。」、`qtyError`、開始・終了の片方だけ「開始と終了の両方を入れてください(片方だけは保存しません)。」、`calcHours` の失敗、時間と合わない「時間と、開始・終了が合いません。どちらかを直してください。」
  - 追加に成功したら、取引先とサービスは残し、時間・開始・終了・1行の欄を空にする。表示の月を、追加した行の月へ移す。
  - 失敗の文: 「この行は保存できませんでした。」。デモ版は「デモ版では、右の選択欄から、決まった取引先とサービスを選んでください。」
  - 欄と1行は、同じ1つの関数(`commit(v)`)を通る。`v = {date, client, service, hours, kind, start, end}`。
  - 切りかえ: 欄→1行のとき、欄が足りていれば1行の文にして入れる(`lineOf`、第9章)。1行→欄のとき、読めた分を欄に入れる。
  - 直す(`startEdit`): 行の中身を、欄にも1行にも入れ、見出しとボタンの文を直し用に替え、入れる欄の最初へ移る。やめる・保存の後は元に戻す。
- 日付の欄の初めの値: 今日。月を替えたとき(直していなければ)、今月なら今日、そうでなければその月の1日にする。

### 8.6 CSVに書き出す(くわしく)(`section#sec-out`)

### 8.7 設定(`section#sec-settings`)と控え(`section#sec-backup`)
- 設定: 見出し「設定(取引先と単価)」。説明の文、`details`(取引先コードとは/請求書ソフトに登録ずみとは/税の設定のわけ方/品目の源泉徴収/源泉徴収)。`#cmsg`・`#imsg`(結果の文)。

## 第9章 1行の読み取り(`parseLine(text, mo)`)

1行の文を、日付・取引先・サービス・時間(または回数)・種類に分けます。`mo` は表示中の月(YYYY-MM)。

### 9.1 区切り方
`normName`(NFKC で全角を半角に)したうえで、空白で区切ります。全角の数字や記号のままでも読めます。

### 9.2 日付
次の形だけを日付とします。

- `^(\d{1,2})[/月](\d{1,2})日?$`(例 `10/21`、`10月21日`)
- `^(\d{4})/(\d{1,2})/(\d{1,2})$`(例 `2026/10/21`)

- 年が無い形では、表示中の月の年を使う。ただし、表示中の月との月の差が6を超えるときは、前の年か次の年にする(12月を表示中の `1/5` → 次の年の1月5日。1月を表示中の `12/28` → 前の年)。具体的には、(書かれた月 − 表示中の月)が6より大きければ前の年、−6より小さければ次の年。
- 存在しない日付(`2/30`)は、日付ではなく「読めない言葉」にする。2つ目の日付も、読めない言葉にする。
- `10-21` のようにハイフンで書いた形は、日付として受けません。時間帯(10時〜21時)として読みます。そのとき日付がまだ読めていなければ、読み取りの札に「日付は 10/21 と書きます」も足します。

### 9.3 時間帯
`^(\d{1,2})(?::(\d{2}))?[-~〜](\d{1,2})(?::(\d{2}))?$`(例 `9:00-11:00`、`9-11`、`9〜11`)。

- 時・分を "HH:MM" の2桁にそろえ、`calcHours` で時間を出す(0.25刻みには丸めない。例 `9:10-10:00` は 0.83)。
- 時が24など範囲外: 読めない言葉(理由「24時は使えません(23:59 まで)」)。終了が開始以前: 読めない言葉(理由「終了は開始より後に」)。

### 9.4 数量
- `^(\d+(?:\.\d+)?)(h|H|時間)$`: 時間数(`1.5h`、`1.5時間`)
- `^(\d+)回$`: 回数(`2回`)
- 同じ種類が2つ目に出たら、読めない言葉にする。

### 9.5 種類
「予定」か「実績」という言葉があれば、その種類。無ければ `kindFor(日付)`(日付が読めていれば)。

### 9.6 取引先・サービスの名前
- 比べ方の下ごしらえ: `squash(n)` = `normName(n)` から空白をすべて除く。`key(n)` = `squash(n)` を大文字にしたもの。`baseKey(n)` = `key(n)` から「株式会社」「有限会社」「合同会社」「(株)」「(有)」「ダミー」を除いたもの。
- 候補は、行や設定にある名前(`candidates()`。デモ版は決まった一覧)。
- 札の文字 `T = key(札)`。`key(名前)` か `baseKey(名前)` が `T` で始まるものが候補。
  - `key` がぴったり同じものが1つだけなら、それ。
  - そうでなければ、`key` か `baseKey` がぴったり同じものが1つだけなら、それ。
  - そうでなければ、候補すべて(2つ以上なら、選ばずに止める)。
- 空白のある名前(例 `山田 太郎`)は、続く言葉を最大3つまでつないで当てる。長いつなぎを先に試す。
- 取引先が決まっていないうちは、先に取引先を当て、そのあとでサービスを当てる。当たった名前は、行には正式な名前で入れる。
- どれにも当たらない言葉は、「読めない言葉」にして、追加させない。

### 9.7 品目の単位による違い
- 時間の品目: 時間帯か時間数のどちらかが必要。どちらも無ければ止める(「時間が分かりません」)。両方あって合わなければ(差が0.005を超える)止める(「時間と、開始・終了が合いません」)。回数の言葉(`2回`)は読めない言葉(「このサービスは時間です」)。
- 回の品目: 回数が無ければ1回。回数が整数で1以上でなければ止める。時間帯は記録しない(札「時間帯は記録しません」)。時間数の言葉(`1.5時間`)は読めない言葉(「このサービスは回数です」)。

### 9.8 結果と札
- 結果: `{ ok, v, parts(札), miss(足りないもの), empty }`。`ok` のとき `v = {date, client, service, hours, kind, start, end}` で、欄と同じ `commit(v)` へ渡す。
- 札(`#qRead` に出す。`読み取り:` のあとに並べる):
  - 読めた札: 丸い枠(`chip-ok`)。日付は「10/21(水)」、表示中の月と違う月なら「 ※11月に入ります」を足す。年が表示中の年と違えば「2027年」を先頭に付ける。時間は「9:00〜11:00(2時間)」か「1.5時間」、回は「1回」、種類は「予定として」「実績として」。
  - 読めなかった札: 赤い点線の枠+文字(`chip-miss`): 「日付が分かりません」「取引先が分かりません」「サービスが分かりません」「時間が分かりません」、候補が複数なら「取引先の候補: X / Y」「サービスの候補: X / Y」、読めない言葉は「「xx」は読めません(理由)」。色だけに頼らず、必ず文字を出す。
  - 何も入っていないとき: 「「日付 取引先 サービス 時間」の順に、空白で区切って入れます。」
- メッセージ(`#fmsg`): 入力中は「まだ足りないもの: …」(足りないものを「、」でつなぐ)。足りているときは「Enterキーでも追加できます。」。追加を押して止まったあとは、赤い太字で「エラー: …を直してから押してください。」とし、`#q` に `aria-invalid="true"` を付け、`#q` へ移る。入力すると、その状態は消える。
- 足りないものの文: 「日付(例 10/21)」「取引先」「取引先(候補がnつ。もう少し書いてください)」「サービス」「サービス(候補がnつ。もう少し書いてください)」「時間(例 9:00-11:00)」「時間と、開始・終了が合いません」「回数(1以上の整数)」「読めない言葉「xx」(理由)」。

### 9.9 行を1行の文にする(`lineOf(行)`)
直すとき、1行の欄に入れる文です。`parseLine(lineOf(行))` が、同じ中身(日付・取引先・サービス・数量・時間帯・種類)に戻らなければなりません。

- 形: `年/M/D 取引先 品目 数量 種類`(空白は1つずつ)。年は4桁、`M/D` は0なし。
- 取引先と品目は `squash`(空白を除く)した名前。
- 数量: 回の品目は、1回のときは書かず、2回以上のときだけ「2回」。時間の品目は、時間帯があれば「09:00-11:00」、なければ「1.5時間」。
- 種類は「実績」か「予定」。

## 第10章 デモ版と build-demo

デモ版は、練習として公開する、流れを見るための版です。

### 10.1 作り方
実用版 `index.html` の `const DEMO=false;` を `const DEMO=true;` に置き換えたものが、デモ版です。それ以外は、1文字も変えません。

### 10.2 build-demo(`tools/build-demo.js`、Node.js)

- `buildDemo(html)` を関数として外に出し(`module.exports`)、テストから使えるようにします。
- 実行: `node tools/build-demo.js`。

## 第11章 見た目(色・文字・大きさ)

CSS は、色の名前(CSS 変数)を `:root` に置き、そのほかの CSS が名前だけを使う形にします。色の値を直接書かないでください(1か所を直せば全体が変わるように)。

### 11.1 色
ライトが初めの値です。ダークは、(a)端末の設定に合わせるとき(`@media (prefers-color-scheme: dark)` の中の `:root:not([data-theme="light"])`)と、(b)ページ側で強制するとき(`:root[data-theme="dark"]`)の両方に、同じ値を書きます。ライトは `:root` と `:root[data-theme="light"]` に書きます。`color-scheme` も合わせます。

### 11.2 コントラストの基準
- 文字: 4.5 : 1 以上(WCAG の相対輝度の式で測る)。測る組み合わせ(文字の色 / 地の色): text/out、text-sub/out、primary/out、danger/out、text-sub/primary-soft、bg/text、toast-btn/text、toast-btn/toast-hover、primary/surface-2。
- 文字以外(枠・印): 3.0 : 1 以上。測る組み合わせ: out-line/out、out-line/bg、c1〜c4 のそれぞれ/surface・surface-2・primary-soft、border/primary-soft、primary/primary-soft、danger/danger-soft、focus/out、focus/primary-soft。
- ライトとダークの両方で測り、全部が合格すること。測る道具は、テスト(第6段)の中に小さく書きます。
- 色だけで意味を伝えません。警告の「エラー:」「注意:」、取引先の名前の文字、予定の点線と実績の塗り、読み取りの札の文字など、必ず文字か形も添えます。

### 11.3 文字と大きさ
- 文字: `"Yu Gothic UI", "Hiragino Sans", "Meiryo", system-ui, -apple-system, "Segoe UI", sans-serif`。
- 大きさ: 本文 16px、小さい文字(注記・ボタン小)14px、`h1` 20px、`h2` 18px、`h3` 16px。行の高さ 1.6。頭の月の数字 56px(幅480px以下は48px)、頭の合計 28px(太字)。1行の入力欄は高さ52px・18px。
- **押せる大きさ**: ボタン・入力欄・選択欄の高さは44px以上(`--tap: 44px`)。小さいボタン(`.btn-sm`)でも36px以上(`--tap-sm: 36px`)。チェックボックスは24px。カレンダーの日のマスは高さ96px以上。
- 余白: 4・8・12・16・24・32px を使う。角丸は 8px(部品)、12px(カード・枠)、16px(記録を入れる箱)。ページの余白は16px(幅600px未満は8px)。
- ボタンの形: 主(塗り)、副(ふち取り)、危険(赤のふち取り)、文字(ふちなし)。ホバーで下線を付け、押している間は1px下げる。押せないときは濃さ50%。キーボードの輪は、3pxの `--focus` を2〜3pxはなして出す(`:focus-visible`)。
- 狭い幅(スマホ)で、横にはみ出さないこと。3列の板は、幅が足りないと縦に並ぶ。表は、表だけが横にスクロールする。
- 動き(アニメーション)は、色の変化 100ms 程度にとどめる。
