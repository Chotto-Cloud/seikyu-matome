# 頼み方 7(チャット用): 自分の請求書ソフトに合わせる(おまけ)

## この段で作る物
このアプリが書き出す明細 CSV を、**お使いの請求書ソフトの CSV 取りこみの形**に変えます。うまく合えば、月末に CSV を取りこむだけで、請求書の「下書き」まで自動で作れます。

このアプリの CSV は、どのソフトにも合わせていません。ソフトごとに、列の名前も並びも違います。だから、合わせるときは、**そのソフトの見本ファイル**が要ります。見本なしで作ると、ほぼ確実に取りこみで断られます。

第6段まで終わってから、必要な人だけ進めてください。Node.js が要ります(見本の1行目を読む道具と、テストに使います)。

## 先に確かめること
- お使いの請求書ソフトに、CSV の取りこみ(一括登録、インポートなど)があるか。無い場合は、この段は進められません。第6段までの CSV を、表計算ソフトで見て使ってください。
- ソフトの**利用規約**を読み、CSV の取りこみを使ってよいか、自動で作った CSV を取りこんでよいかを確かめます。
- できれば、練習用のアカウントや、無料のプランで試します。仕事で使っている、本物の取引先が入ったアカウントでは試さないでください。

## 準備: 見本ファイルを手に入れて、1行目を読む
1. お使いの請求書ソフトの**公式ヘルプ**で、「CSV 取りこみ」「CSV アップロード」などの説明を探します。
2. 説明の中にある**見本ファイル(テンプレート)**をダウンロードします。ふつう、1行目に列の名前が並んだ CSV です。
3. 見本ファイルを、**開かずに**(Excel などで開いて保存し直さずに)、作業フォルダーの `sample/` に入れます。名前は、英数字にします(例: `sample/mysoft見本.csv`)。
   - 開いて保存し直すと、文字コードや列の名前が変わることがあります。
   - 見本の中身が、本物の取引先の名前だったら、使わないでください。見本は、1行目の列名だけがあれば足ります。
4. **1行目を、道具で読みます。** AI に打ち直させません。

   ```
   node 作り方一式/tools/read-sample-header.js sample/mysoft見本.csv
   ```

   次が出ます。
   - BOM(先頭の目印)の有無、文字コード(UTF-8 として読めるか)、改行(CRLF か LF か)、列の数。
   - `const HDR_LINES=["列1","列2",…];` の1行。これを、AI に**そのまま**貼ります。
   - 手で写す場合(Node.js が使えないとき)は、メモ帳で見本を開いて、1行目だけを写します。保存はしません。Excel では開きません。ただし、手で写すと、全角と半角の違いを落としやすいので、道具をおすすめします。
5. **BOM は、見本のファイルに合わせます。** 見本に BOM が無いなら、CSV にも付けません。ソフトによって違います(試した時は、3種の CSV とも、BOM を外す必要がありました)。文字コードと改行も、見本に合わせます。
6. 取引先を先に登録する決まりがあるか、同じ請求書番号を二重に取りこむとどうなるか、も、ヘルプで確かめます。

## 貼る物
**新しいチャットを開きます。** 次を添付(または貼る)します。

1. 下の「AI に貼る文」(本文)
2. `仕様書.md` の第4章(添付なら、`仕様書.md` ごと)
3. **第6段まで終わった `index.html`**(最新のもの)
4. 準備の4で出た、道具の出力(BOM・文字コード・改行の表示と、`const HDR_LINES=…` の1行)

- 見本ファイルの2行目以降は、貼りません。1行目だけで足ります。
- 本物の取引先名・金額・振込先は、AI に貼りません。

## AI に貼る文

```
あなたは、Webアプリを作る手伝い役です。私は初心者です。分かりやすい日本語で答えてください。

「請求まとめ」の明細CSV(いまはふつうのCSV。列の並びは仕様書4.2のとおり)を、私が使っている請求書ソフトの「CSV取りこみ」の形に変えたいです。
このあとに、「仕様書の第4章」「いまの index.html」「請求書ソフトの見本ファイルの1行目を読む道具の出力」を貼ります。

【先にしてほしいこと】コードを変える前に、次の2つの表を作って、私に見せてください。
1. 対応表: 見本ファイルの列(1列目から順に)ごとに、「このアプリのどの値を入れるか」。例: 「3列目 = 発行日」。
   - 対応するものが無い列は、「空にする」か「固定の値を入れる」か、私に聞いてください。決めつけないでください。
   - このアプリに無い値が必須の列があれば、教えてください(作り話で埋めないでください)。
   - 1つの請求書を1行にして、明細を横に並べる形のソフトもあります。見本がそういう形かどうかも、判断して教えてください。
2. 消える列の一覧: このアプリの明細CSV(21列)のうち、合わせた形に入らない列(例: 種類(予定/実績)、日付、開始、終了)を、全部挙げてください。それぞれ、消えると何が困るかも、一言で書いてください。特に「種類(予定/実績)」が消えるなら、予定が実績と見分けがつかなくなることを、はっきり書いてください。
私が「その表でよい」と言ってから、コードを変えてください。

【見出しの決まり】
- 見本の1行目は、私が貼った `const HDR_LINES=[…];` の1行です。それを、**そのまま、1文字も変えずに**使ってください。
- 部品をつなげて見出しを作ること、打ち直すこと、言いかえること、並べ替えること、全角と半角を入れかえることは、すべて禁止です。
- BOM の有無、文字コード、改行は、貼った道具の出力(見本の実際の姿)に合わせてください。

【変える所】
0. **index.html は、そのまま残してください。** index.html を写して、`index-mysoft.html`(英数字の名前)を作り、変えるのは写しだけにしてください。
1. index-mysoft.html の HDR_LINES を、貼った1行に置き換える。
2. 明細CSVを作る関数 invoiceCsv() を、対応表のとおりに作り直す。
3. BOM・文字コード・改行は、見本に合わせる。ブラウザだけで作れない場合は、そう言ってください。
4. ファイル名は、分かりやすい名前にしてよい。
5. ソフトに取引先CSVや品目CSVの取りこみもあり、見本の1行目も貼ってあるなら、同じように HDR_CUS と customerCsv()、HDR_ITEM と itemCsv() も合わせる。見本が無いものは、変えない。
6. 警告 problems() に、取りこみで断られそうな点の警告を足す(index-mysoft.html の中だけ)。
   - 合わせた形に取引先の登録番号・メール・郵便番号・電話の列があるなら、それぞれの形の警告。見本の説明(ヘルプの例)にある形に合わないときに出す。ヘルプに「この形でないと断る」と書いてあるものは「止める」、ないものは「※」で通す。
   - 必須の列が空になる、日付の形が違う、数字にカンマが入る、のような点も、見本の説明から拾って足す。
   - 合わせた形に「種類(予定/実績)」の列が無いのに、「予定も含める」がオンのとき、または予定が書き出しに入るとき: **止める警告**にする(予定が実績として取りこまれてしまうため)。
7. デモ版は、合わせた版からは作らない。ふつうの index.html から、build-demo で作る。

【変えない所】
- <meta http-equiv="Content-Security-Policy" …>(外への通信を止める設定)
- 入力した文字を画面に出すときは textContent か value を使う(innerHTML に入れない)
- 外へ送る通信(fetch など)を足さない
- 金額・税の計算はしない(単価と数量を渡すだけ)
- const DEMO=false; の行
- CSV以外の機能(入力、設定、控え、元に戻す、カレンダーなど)
- 元の index.html と、既にあるテスト(tests/csv-check.test.js など)

【自分で確かめてください】
- 別のテストファイル tests/mysoft-check.test.js を作ってください(既にあるテストは直さない)。index-mysoft.html を node:vm で動かします。内容:
  (a) sample/ に置いた見本ファイル**そのもの**を fs で読み(貼った文ではなく)、その1行目と HDR_LINES が1文字も違わない。見本ファイルが無いときは、飛ばさずに失敗にする。
  (b) ダミーのデータ(ダミーA社、ダミー作業、架空銀行 サンプル支店 普通 0000000)で作った CSV の、全部の行の列の数が、見本の1行目の列の数と同じ。
  (c) CSV の BOM の有無・改行が、見本ファイルと同じ。
  (d) 予定を含めて書き出すと、(種類の列が無い形なら)止まる。
  (e) 形の警告が、「a」のような値で出る。
- 日付は日本時間に固定してください(process.env.TZ = "Asia/Tokyo")。

【実行について】あなたがコードやテストを実行できない場合は、「未実行」と書き、私が流すコマンドを出してください。結果は、私が貼ってから判断してください。実行していないのに「通りました」とは書かないでください。

【出力のしかた】
- 最初に、対応表と、消える列の一覧だけを出す。私が「よい」と言ったら、index-mysoft.html の**変えた関数と定数**を、置き換え先の名前つきで出す(全文でなくてよい)。「関数 名前 を丸ごと入れ替え」「名前 のすぐ後ろに足す」と、場所を書く。そのあとに、tests/mysoft-check.test.js の全文。
- 最後に、変えた所と理由を、短い一覧で書く。
```

### 関数の入れ替え方(例)
AI が「関数 `invoiceCsv` を丸ごと入れ替え」と書いて、新しい `function invoiceCsv() { … }` を出したら、次のようにします。

1. `index-mysoft.html` をエディタ(メモ帳など)で開く。
2. 「invoiceCsv」で検索して、`function invoiceCsv() {` を見つける。
3. その関数の、始まり(`function` の行)から、終わりの `}`(同じ深さの閉じ)までを、**まるごと選んで消す**。
4. AI が出した関数を、同じ場所に貼る。
5. 保存して、`node --test tests/mysoft-check.test.js` を流す。

「名前 のすぐ後ろに足す」のときは、その関数の終わりの `}` の次の行に貼ります。定数(`HDR_LINES`)は、`const HDR_LINES=…;` の1行を、まるごと入れ替えます。

## 確かめ方(道具で確かめる → ダミーで取りこむ → 下書きで中身を見る → 下書きは消す)
`確かめ方.md` の「7. 自分の請求書ソフトで試す」に従います。要点だけ書きます。

1. 道具で確かめる。
   - `node 作り方一式/tools/check-headers.js index-mysoft.html - sample/mysoft見本.csv` が、「同じです」と「飛ばし(skipped): 0件」を出す。
   - `node --test tests/mysoft-check.test.js` が、`fail 0` かつ `skipped 0`。
   - 元の `node --test tests/csv-check.test.js` も、通る。
2. 試しに入れる値(ダミー)。**空でよい欄は、空にします。** 入れるなら、ソフトのヘルプの例と同じ形の架空の値にします(登録番号は T+13桁の数字、メールは @ の入った形、郵便番号は 123-4567、電話は数字とハイフン)。「a」のような1文字は入れません(試した時は、形のチェックで断られました)。
3. アプリで「ダミーを入れて試す」を押し、合わせた形の CSV を保存する。
4. **取りこむ順番は、取引先 → 品目 → 明細。** 取引先コードは、ソフトの一覧とそろえる。
5. 保存した CSV を、**開かずに**、ソフトの CSV 取りこみから、そのまま取りこむ。
6. エラーが出たら、出た文をそのまま AI に貼って、直してもらう(貼るのは、ダミーのデータの CSV だけです)。
7. 取りこめたら、ソフトの画面で**下書き**の中身を見る。**発行はしません。**
   - 取引先、日付、品目、数量、単位、単価、合計が、ダミーのとおりか。
   - 振込先や、件名が入っているか。
   - 税の計算結果が、ソフトの設定どおりか(このアプリは、税の計算をしません。ソフトの設定が使われます)。
8. 確かめ終わったら、**下書きと、ダミーの取引先を、ソフトの画面で消します。** アプリでも「ダミーを消す」を押します。

## よくある失敗
- **1行目を1文字でも変えると、断られる**: 見本の列名は、括弧の中の説明文も含めて、そのまま使います。試した時は、1行目の括弧の全角・半角が見本と違って、断られました。AI に打ち直させず、道具の出力をそのまま貼ります。そして `check-headers.js` で比べます。
- **BOM**: 見本のファイルに合わせます。ソフトによって違います。試した時は、3種の CSV とも、BOM を外したら通りました。付いているか、付いていないかを、見本の実際の姿(道具の出力)で確かめます。
- **文字コード**: UTF-8 のつもりが、ソフトは Shift-JIS だった(または逆)。文字化けしたり、「文字コードが正しくありません」と断られたりします。見本ファイルの文字コードに合わせます。
- **試しの値の形**: 登録番号・メール・郵便番号・電話に、「a」のような値を入れると、形のチェックで断られます。空にするか、ヘルプの例と同じ形の架空の値にします。
- **登録済みの取引先を二重に送る**: ソフトに取引先がもう登録されているのに、取引先 CSV も取りこむと、重複で断られることがあります。アプリでは、取引先に「請求書ソフトに登録済み」のチェックを付けると、取引先CSVに入らなくなります。
- **同じ請求書番号を二重に送る**: 同じ月の CSV をもう一度取りこむと、請求書番号の重複で断られる(または、二重にできてしまう)ことがあります。作り直すときは、ソフトの下書きを先に消します。
- **予定が実績として取りこまれる**: 合わせた形に「種類」の列が無いと、予定の行も実績として入ります。「予定も含める」はオフのままにします。
- **Excel で開いて保存し直す**: 文字コードや列の形が変わって、断られます。取りこむ CSV は、開かずに使います。
- **チャットの AI が「通りました」と言う**: 実行していないことが多いです。コマンドは自分で流し、結果を自分で見ます。

## 注意
- ソフトの**利用規約**を、必ず読んでください。自動で作った CSV の取りこみが、禁止されているソフトもあるかもしれません。
- **本物のデータを AI に貼らない**: 取引先名、金額、振込先、住所、電話、メール、控えのファイル、ソフトの画面のスクリーンショットは、貼りません。ダミーだけを使います。
- **合わせた版(`index-mysoft.html`)は、自分用として手元だけに置きます。公開しません。** ソフト固有の言葉が入るためです。
- 取りこんで「下書き」ができても、請求書は、**発行する前に、必ず自分で中身を確かめてください。**
- ソフトの CSV の形は、変わることがあります。取りこみで急に断られたら、公式ヘルプで新しい見本を探し、この段をやり直します。
- 練習として作った、非公式の、無保証の資料です。うまく動くことは、お約束できません。
