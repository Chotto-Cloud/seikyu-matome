# 頼み方 6: テストと見直し

## この段で作る物

- 守る決まり(通信しない、`innerHTML` を使わない、など)を、テストで見張る。
- 批判的な見直しを、別の AI に頼む。

仕様書で従う所: 第2章、第4章、第7章、第9章、第11章。

## 6-1 テストをそろえる

### AI に貼る文

```

3. innerHTML の使用が、仕様書2.3の例外(設定の2つの表の見出しの固定文字)だけ。入力された文字を innerHTML に入れていない。

10. 税区分と源泉: 各行の「税区分」(10%・8%(軽減)・非課税)と「源泉徴収」(なし・10%・10.21%)の列に、品目の設定がそのまま書かれる。率が混ざっても止まらない。
C. 動き
```

## 6-2 批判的な見直し(別の AI に)

作った AI とは**別の AI(新しい会話)**に頼みます。作った本人に頼むと、自分の作った物をほめがちです。仕様書と `index.html` だけを渡し、「あなたの考えを先に言って」と頼まないでください。

### 貼る物
**新しいチャットを開きます**(6-1 のチャットとは別にします)。下の「AI に貼る文」(本文に貼ります)、`仕様書.md`(添付)、第6-1 まで終わった `index.html`(添付)。テストと、あなたの感想は貼りません。

### AI に貼る文

```
あなたは、厳しい目を持つレビュアーです。私は初心者です。分かりやすい日本語で答えてください。

これから「仕様書」と、それに従って作った index.html を貼ります。index.html を直さずに、次の5つの立場で、問題を探してください。ほめる必要はありません。見つかった問題だけを、重い順に書いてください。確かめていないことは、「確かめていない」と書いてください。見たことと、推測は、分けてください。

1. 記録の係: データが消える、壊れる、二重になる可能性。保存・控え・元に戻す・名前の変更・削除・月をまたぐ日付。
2. 守りの係: 外への通信、innerHTML、CSP、入力の扱い、ファイルとして開いたときの注意の文。
3. 編集者: 仕様書と index.html の食い違い。仕様書にあるのに作られていない物、作られているのに仕様書に無い物。
4. 読者: 画面の文言が分かりにくい所、色だけに頼っている所、押せる大きさ、キーボードだけで使えるか、読み上げで困る所。
5. 校正: 誤字、言い回しの不統一、用語のゆれ。

書き方: 1件ごとに、(1)どこ(関数名か画面の部品のID)、(2)何が起きるか、(3)なぜ問題か、(4)直し方の案を1つ。直し方は、仕様書の決まり(CSV の見出しの行、CSP、innerHTML を使わないこと、税の計算をしないこと)を壊さないものだけにしてください。
最後に、「直さなくてよいと思うもの」も、理由つきで短く書いてください。
```

### 見直しの結果の扱い
1. 出てきた指摘を、**全部は直しません**。次の順に分けます。
   - すぐ直す: データが消える、外へ送られる、CSV の形が壊れる、のような取り返しがつかない物。
   - 記録して、まとめて直す: 文言、見た目、細かい不統一。
   - 直さない: 好みの問題、仕様書の決まりに反する案。
2. 直すと決めた物だけを、AI に頼みます。頼む文の例:

```
次の指摘を直してください。ほかの所は変えないでください。直したあと、変えた関数と理由を一覧にしてください。仕様書のCSVの見出し、CSP、innerHTMLを使わないこと、税の計算をしないこと、const DEMO=false; の行は、変えないでください。
(ここに、直すと決めた指摘を貼る)
```

3. 直したら、6-1 のテストをもう一度流します。CSV が見本と1文字違わないことも、もう一度確かめます。

### 終わったと言える条件
- [ ] 見直しの結果を3つ(すぐ直す/まとめて直す/直さない)に分けた。
- [ ] 「すぐ直す」を直し、テストが全部通る。
- [ ] 見本のCSVと1文字違わない。
- [ ] `確かめ方.md` の「8. 片付け」まで終えた。
