## 終わったと言える条件

- [ ] 第1段の条件が、まだ全部通る。
- [ ] 「ダミーを入れて試す」で、ダミーの行5件(ダミーA社に3件、ダミーB社に2件)と、ダミーの設定が入る。もう一度押しても、同じ行は増えない。「元に戻す」で、行も設定も押す前に戻る。
- [ ] 「ダミーを消す」で、ダミーの行と設定だけが消え、自分で入れた行は残る。
- [ ] 設定で、取引先と品目を登録・編集できる。使っている名前は削除できない。名前を変えると、行の名前も変わる。
- [ ] 品目の単位を「回」にすると、入れる欄が「回数」になり、2.5 を入れると「回数は、1以上の整数で入れてください。」と出る。
- [ ] 単価を、月を替えて変えると、前の月の単価は変わらない(履歴)。
- [ ] 「控えを保存」で JSON のファイルができ、データを消したあとに「控えから戻す」で戻る。壊れたファイルを選ぶと、今のデータは変わらずに、文で知らせる。
- [ ] 古い形の控え(`tax` や取引先ごとの `wh` を含む)でも読める。
- [ ] コードに `innerHTML` が無い(仕様書2.3の例外[設定の2つの表の見出しの固定文字]だけ)。

## 人が確かめること

1. ダミーを入れ、カードの「実績にする」「削除」のあとに、画面の下の帯の「元に戻す」で戻る。帯が勝手に消えない。
2. 「控えを保存」→ブラウザのデータを消す(または別のブラウザで開く)→「控えから戻す」→同じ行が出る。
3. 取引先の名前を `__proto__` や `constructor` にして登録しても、画面が壊れない。
4. 本物のブラウザで、Console に赤いエラーが出ていない。

## うまくいかないとき
- 第1段で動いていた所が壊れた: 「第1段の条件が通らなくなりました。直前のコードとの違いを見て、元に戻さずに直してください」と頼みます。
- 古い形の控えが読めない: 仕様書3.3の「品目まわり」の引っ越しの決まりを、AI に読み直してもらいます。
