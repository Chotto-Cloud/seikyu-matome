# 頼み方(Code 用): 一気に版

## この版は何か
ファイルを書き換えられて、コマンドも自分で流せる AI の道具(Claude Code など)向けです。**1回渡すだけで、AI が仕様書に沿って、第1段から第6段までを順に進めます。** 各段で、テストと確かめの道具を AI 自身が流し、合格してから次へ進みます。人が確かめる所(画面の見た目、ソフトへの取りこみ)だけを、最後に一覧で出させます。

チャットに貼る形(`チャット用/`)と中身は同じです。違うのは、段ごとの貼り直しが要らないことと、確かめを AI が実行することです。

## 準備
1. 空の作業フォルダーを作ります(例: `seikyu`)。そこで Code を開きます。
2. 次の2つを、作業フォルダーにコピーします。
   - `作り方一式/` フォルダーごと(中の `仕様書.md`・`tools/`・`チャット用/` を使います)
   - `sample/明細_見本_A社.csv`(`sample/` フォルダーを作って入れます。**開かずに**コピーします)
3. Node.js 20 以上が入っているか、`node --version` で確かめます。
4. 本物の取引先名・金額・振込先は、使いません。ダミーだけです。

作業フォルダーは、こうなります。

```
seikyu/
  作り方一式/   … 仕様書.md、確かめ方.md、tools/、チャット用/、Code用/
  sample/       … 明細_見本_A社.csv
  (ここに、AI が index.html、tests/、tools/build-demo.js、docs/、_headers を作る)
```

## AI に渡す文
次を、Code の入力欄に貼ります。

```
あなたは、この作業フォルダーで、ファイルを書き換え、コマンドも実行できる開発の手伝い役です。私は初心者です。分かりやすい日本語で答えてください。

「請求まとめ」という小さなWebアプリを、作り方一式/仕様書.md に従って、一から作ってください。第1段から第6段まで、順に、最後まで進めてください。途中で私に確認を取らなくて構いません。ただし、次の場合だけは、作らずに止まって、私に質問してください。
  - 仕様書に書いていなくて、判断がつかないとき(あなたは完成見本を見られません。見本との比べは、人がします。迷ったら質問)。
  - 本物のデータが必要になったとき。
  - 仕様書どうしが食い違うとき。

【段の中身】各段で作る物と、従う章は、作り方一式/チャット用/ の次のファイルの「AI に貼る文」と同じです。それぞれ読んで、その【従う所】【やること(足す物)】【作らない物】に従ってください。ただし、その文の中の「貼ります」「全文を出してください」は、無視してください(あなたはファイルに直接書きます)。
  第1段 頼み方_1_試作品.md
  第2段 頼み方_2_データと保存.md
  第3段 頼み方_3_CSV3種.md
  第4段 頼み方_4_画面と1行.md(4-1、4-2、4-3の順)
  第5段 頼み方_5_デモ版.md
  第6段 頼み方_6_テストと見直し.md の 6-1(テスト)

【各段の進め方】1段ずつ、次の順にします。
  1. その段の分を作る。
  2. その段の「終わったと言える条件」の全部を、自分で確かめる。確かめられる物は、テストか道具にして、実際に流す。
  3. 流した結果(コマンドと、終わりの集計)を、短く記録する。流していない物は「未実行」と書く。
  4. 全部合格してから、次の段へ進む。落ちたときは、テストを緩めずに、まず index.html の側の誤りを疑って直す。直しても通らないときは、原因の見立て(index.html の誤りか、テストの誤りか)を書いて、私に質問する。
  前の段の条件は、次の段でも、通り続けること(流し直す)。

【必ず流す物】
  - 第3段から: node --test tests/csv-check.test.js
  - 第3段から: node 作り方一式/tools/check-headers.js index.html 作り方一式/仕様書.md sample/明細_見本_A社.csv
  - 第4段: node --test tests/line-check.test.js、node --test tests/contrast.test.js
  - 第5段: node tools/build-demo.js、node --test tests/demo-check.test.js、index.html と docs/index.html の違いが const DEMO= の1行だけであること
  - 第6段: node --test でテスト全部(実用版・デモ版の両方。環境変数 APP_HTML で切りかえ)
  - 合格の条件: fail 0、かつ skipped 0。check-headers.js は「すべて同じです」と「飛ばし(skipped): 0件」。
  - 見本の CSV が無いとき、またはテストが見本を読めないときは、飛ばさずに失敗にする。
  - 第1・2段は、条件のうち機械で確かめられる物(CSP の行、innerHTML・fetch( ・http://・<script src=・<link が無い、const DEMO=false; が1か所、保存の名前)を、tests/base-check.test.js にして流す。

【見出しの決まり】HDR_LINES・HDR_CUS・HDR_ITEM は、仕様書4.2・4.3・4.4の行を、1文字も変えずに、文字列の配列として書く。部品をつなげて作ることは禁止。

【6-1 のあと】わざと壊す確かめ(HDR_LINES の1文字を変える、fetch("x") を足す、innerHTML に入力値を入れる、色を薄くする)を、自分で行い、それぞれテストが落ちることを見せてから、元に戻す。

【6-2 の見直し】別の AI による批判的な見直しは、あなたはしない。最後の報告に、「6-2 は人が別の会話で行う」と書く。

【守ること】
  - 本物の取引先名・金額・振込先を、書かない・使わない。ダミーだけ(実用版はダミーA社・ダミー作業・ダミー相談、デモ版はA社・作業サービス・相談サービス、振込先は 架空銀行 サンプル支店 普通 0000000)。
  - 外へ通信しない。innerHTML を使わない。税・源泉の計算をしない。
  - 作り方一式/ の中のファイルと sample/ は、書き換えない。
  - git のコミットと push は、私が頼むまでしない。

【最後の報告】短く、次を書く。
  1. 作った物の一覧(ファイル名と大きさ)。
  2. 各段の合格の記録(流したコマンドと集計。未実行の物は「未実行」)。
  3. 質問して止まった所、仕様書から外れた所と理由。
  4. 人が確かめる所の一覧(下の「人が確かめること」をそのまま、作った物に合わせて)。
```

## 人が確かめること(AI が最後に出します)
AI は、画面を見られません。次は、必ず自分の目で確かめてください(`確かめ方.md` の1・2・6)。

1. 本物のブラウザ(Chrome か Edge)で `index.html` をファイルとして開く。上に黄色い枠や赤い枠が出ていない。F12 の Console に赤いエラーが無い。
2. 「ダミーを入れて試す」を押し、予定・実績のカードが出る。「明細CSVを保存」で `明細_2026-10.csv` ができる。Excel などで開いて見たら、保存し直さずに閉じる。
3. 画面の見た目を、画面ごとに最後に1回だけ。幅(広い・約600px・約375px)、色(ライト・ダーク)、別窓(削除・カレンダー・取引先・品目)。見るのは、(1)文字が読める、(2)ボタンが押せる大きさ、(3)横にはみ出さない、(4)別窓が開いて Esc で閉じる、の4つ。
4. Wi-Fi を切っても動く。
5. `docs/index.html` を開き、実用版とは別の保存場所を使っていること(実用版で入れた行が出ない)。
6. 仕様書の第7章の警告を、ダミーで1つずつ起こして、画面に文が出る(単価を空にする、振込先を空にする、予定を残す、など)。
7. 第6段の見直し(6-2)は、別の会話で行う(`チャット用/頼み方_6_テストと見直し.md` の 6-2)。
8. 自分の請求書ソフトに合わせるなら、`Code用/頼み方_7_自分のソフトに合わせる.md` へ。

## うまくいかないとき
- AI が途中で止まって質問してきた: 答えが分からなければ、仕様書の該当の章を一緒に読んで、「仕様書どおりに」と伝えます。見本(`index.html` の完成版)で確かめられるなら、人が見て伝えます。
- 長くなって、AI が前の決まりを忘れ始めた: 会話を新しくして、「作り方一式/仕様書.md を読んで、いまの index.html の続きから、第N段を進めてください。前の段の条件は、通り続けること」と頼みます。
- 「通りました」と言うが、結果が出ていない: 「コマンドと、終わりの集計をそのまま見せてください」と頼みます。自分で `node --test …` を流して見るのが、いちばん確かです。
