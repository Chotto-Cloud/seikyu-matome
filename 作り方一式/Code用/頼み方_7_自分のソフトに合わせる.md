# 頼み方 7(Code 用): 自分の請求書ソフトに合わせる(おまけ)

## この段で作る物
このアプリが書き出す明細 CSV を、**お使いの請求書ソフトの CSV 取りこみの形**に変えます。うまく合えば、月末に CSV を取りこむだけで、請求書の「下書き」まで自動で作れます。

Code 用は、AI がファイルを書き換え、コマンドも自分で流せる道具(Claude Code など)向けです。**見本との比べ合わせは、AI 自身にさせます。** 人がするのは、決めること(対応表、消える列)と、ソフトに取りこんで下書きを見ることだけです。

このアプリの CSV は、どのソフトにも合わせていません。ソフトごとに、列の名前も並びも違います。だから、**そのソフトの見本ファイル**が要ります。見本なしでは、ほぼ確実に取りこみで断られます。

第6段まで(または `Code用/頼み方_一気に版.md` を最後まで)終わってから、必要な人だけ進めてください。

## 先に確かめること
- お使いの請求書ソフトに、CSV の取りこみ(一括登録、インポートなど)があるか。無い場合は、この段は進められません。
- ソフトの**利用規約**を読み、CSV の取りこみを使ってよいか、自動で作った CSV を取りこんでよいかを確かめます。
- できれば、練習用のアカウントや、無料のプランで試します。仕事で使っている、本物の取引先が入ったアカウントでは試さないでください。

## 準備: 見本ファイルを手に入れる(ここは人がします)
1. お使いの請求書ソフトの**公式ヘルプ**で、「CSV 取りこみ」などの説明を探し、**見本ファイル(テンプレート)**をダウンロードします。
2. 見本ファイルを、**開かずに**(Excel などで開いて保存し直さずに)、作業フォルダーの `sample/` に、英数字の名前で入れます(例: `sample/mysoft見本.csv`)。
   - 見本の中身が、本物の取引先の名前だったら、使わないでください。1行目の列名だけがあれば足ります。
3. 取引先を先に登録する決まりがあるか、同じ請求書番号を二重に取りこむとどうなるか、を、ヘルプで確かめておきます。

## AI に渡す文
Code の入力欄に、次を貼ります。見本のファイル名は、自分の物に替えます。仕様書は、`作り方一式/仕様書.md` を読ませます。

```
あなたは、この作業フォルダーで、コマンドも実行できる開発の手伝い役です。私は初心者です。分かりやすい日本語で答えてください。

「請求まとめ」の明細CSV(いまはふつうのCSV。列の並びは 作り方一式/仕様書.md の4.2)を、私が使っている請求書ソフトの「CSV取りこみ」の形に変えたいです。見本ファイルは sample/mysoft見本.csv です(開かない・書き換えない・コピーして加工しない)。

【進め方】次の順に、自分で進めてください。実行した物は、コマンドと結果を見せてください。実行していない物は「未実行」と書いてください。

手順1(読む): node 作り方一式/tools/read-sample-header.js sample/mysoft見本.csv を流す。BOM の有無・文字コード・改行・列の数・const HDR_LINES=… の1行を、そのまま見せる。

手順2(私に聞く): コードを変える前に、次の2つの表を作って、私に見せ、「その表でよい」と言われるまで待つ。
  1. 対応表: 見本の列(1列目から順に)ごとに、「このアプリのどの値を入れるか」。対応が無い列は、「空にする」か「固定の値を入れる」か、私に聞く(決めつけない)。このアプリに無い値が必須の列があれば、教える(作り話で埋めない)。見本が「1請求書=1行で明細が横に並ぶ形」かも判断する。
  2. 消える列の一覧: 明細CSV(21列)のうち、合わせた形に入らない列(例: 種類(予定/実績)、日付、開始、終了)を全部挙げ、消えると何が困るかを一言ずつ。特に「種類(予定/実績)」が消えるなら、予定が実績と見分けがつかなくなることを、はっきり書く。

手順3(作る): 私の「よい」のあとで、次を行う。
  - index.html は、そのまま残す。写して index-mysoft.html を作り、変えるのは写しだけ。
  - HDR_LINES は、手順1の出力の const 行を、そのまま貼る。部品をつなげて作る・打ち直す・言いかえる・並べ替える・全角半角を直す、は禁止。
  - invoiceCsv() を対応表のとおりに作り直す。BOM・文字コード・改行は、手順1で分かった見本の姿に合わせる(見本に BOM が無ければ付けない)。ブラウザだけで作れない場合(Shift-JIS など)は、そう言って私に聞く。
  - 取引先CSV・品目CSVの取りこみもあり、見本があるときだけ、HDR_CUS・customerCsv()・HDR_ITEM・itemCsv() も合わせる。見本が無い物は変えない。
  - problems() に、取りこみで断られそうな点の警告を足す(index-mysoft.html の中だけ)。登録番号・メール・郵便番号・電話の形(ヘルプの例にある形に合わないとき)、必須の列が空、日付の形、数字にカンマ、など。ヘルプに「この形でないと断る」とあるものは「止める」、ないものは「※」で通す。
  - 合わせた形に「種類(予定/実績)」の列が無いのに、予定が書き出しに入るとき(「予定も含める」がオン)は、止める警告にする。
  - デモ版は、合わせた版からは作らない。ふつうの index.html から build-demo で作る。
  - 変えない物: CSP の meta、innerHTML を使わないこと、外への通信を足さないこと、税・金額の計算をしないこと、const DEMO=false; の行、CSV以外の機能、元の index.html と既にあるテスト。

手順4(自分で確かめる): 別のテストファイル tests/mysoft-check.test.js を作る(既にあるテストは直さない)。index-mysoft.html を node:vm で動かし、次を確かめる。
  (a) sample/mysoft見本.csv そのものを fs で読み、その1行目と HDR_LINES が1文字も違わない。見本ファイルが無いときは、飛ばさずに失敗にする。
  (b) ダミーのデータ(ダミーA社、ダミー作業、架空銀行 サンプル支店 普通 0000000)で作った CSV の、全部の行の列の数が、見本の1行目の列の数と同じ。
  (c) CSV の BOM の有無と改行が、見本ファイルと同じ。
  (d) 予定を含めて書き出すと(種類の列が無い形なら)止まる。
  (e) 形の警告が、「a」のような値で出る。
  次を流し、結果を見せる。全部、fail 0、skipped 0 になるまで直す(テストを緩めて通さない。まず index-mysoft.html の誤りを疑う)。
    node 作り方一式/tools/check-headers.js index-mysoft.html - sample/mysoft見本.csv
    node --test tests/mysoft-check.test.js
    node --test tests/csv-check.test.js   (元の版が壊れていないことの確かめ)

手順5(見本との比べ合わせ。AI 自身で): ダミーのデータで合わせた形の CSV を実際に作り(テストの中でよい)、見本と次の表を作って見せる。
  | 項目 | 見本 | 作った CSV | 同じか |
  BOM、文字コード、改行、最後の行のあとの改行、列の数、1行目の文字。
  同じでない行があれば、直してから、もう一度流す。

手順6(止まる): ここから先は私がします。私に、「ソフトに取りこむ手順」(確かめ方.md の7-4)と、ダミーCSVの保存場所を伝えて、終わる。

【ほかの決まり】
- 本物の取引先名・金額・振込先は、使わない・書かない。ダミーだけ。
- 試しの値: 空でよい欄は空。入れるなら、ソフトのヘルプの例と同じ形の架空の値(登録番号は T+13桁の数字、メールは @ 入り、郵便番号は 123-4567、電話は数字とハイフン)。「a」のような1文字は入れない。
- 合わせた版(index-mysoft.html)は自分用で、手元だけに置く。公開物に入れない。
- git のコミットと push は、私が頼むまでしない。
```

## 人がすること(AI が止まったあと)
1. 対応表と消える列の一覧を見て、「よい」か「直して」を言う(手順2)。
2. ソフトに取りこむ。`確かめ方.md` の「7-4. 取りこむ」に従います。
   - **取りこむ順番は、取引先 → 品目 → 明細。** 取引先コードは、ソフトの一覧とそろえる。
   - 保存した CSV は、**開かずに**取りこむ。
3. 断られたら、ソフトが出した文を、そのまま AI に渡して、直してもらう(ダミーのデータの CSV だけを渡します)。
4. 「下書き」の中身を見る。**発行はしません。** 確かめ終わったら、下書きとダミーの取引先を、ソフトの画面で消す。

## よくある失敗
- **1行目を1文字でも変えると、断られる**: 試した時は、1行目の括弧の全角・半角が見本と違って、断られました。AI に打ち直させず、道具(`read-sample-header.js`)の出力をそのまま使わせます。`check-headers.js` が、見本のファイルそのものと比べます。
- **BOM**: 見本のファイルに合わせます。ソフトによって違います。試した時は、3種の CSV とも、BOM を外したら通りました。
- **文字コード**: 見本が Shift-JIS のとき、ブラウザだけでは作りにくいです。AI に、どうするか聞かせます。
- **試しの値の形**: 登録番号・メール・郵便番号・電話に「a」のような値を入れると、形のチェックで断られます。空にするか、ヘルプの例と同じ形の架空の値にします。
- **登録済みの取引先を二重に送る / 同じ請求書番号を二重に送る**: 重複で断られる(または、二重にできてしまう)ことがあります。作り直すときは、ソフトの下書きを先に消します。
- **予定が実績として取りこまれる**: 「種類」の列が無い形では、「予定も含める」はオフのままにします。
- **Excel で開いて保存し直す**: 文字コードや列の形が変わって、断られます。

## 注意
- ソフトの**利用規約**を、必ず読んでください。自動で作った CSV の取りこみが、禁止されているソフトもあるかもしれません。
- **本物のデータを AI に渡さない**: 取引先名、金額、振込先、住所、電話、メール、控えのファイル、ソフトの画面のスクリーンショットは、渡しません。ダミーだけを使います。
- **合わせた版(`index-mysoft.html`)は、自分用として手元だけに置きます。公開しません。** ソフト固有の言葉が入るためです。
- 取りこんで「下書き」ができても、請求書は、**発行する前に、必ず自分で中身を確かめてください。**
- ソフトの CSV の形は、変わることがあります。取りこみで急に断られたら、公式ヘルプで新しい見本を探し、この段をやり直します。
- 練習として作った、非公式の、無保証の資料です。うまく動くことは、お約束できません。
